# 04：查询投影、分组分页与性能

Status: ready-for-agent
Blocked by: 02, 03

Parent: [全量重构技术方案](../spec.md)

## 目标

让读查询按资源和页工作，消除单详情的全库资料解析与前端全量聚合，同时保持最新的媒体库分组、最近添加、搜索和人物语义。

## 范围

- 实现轻量 catalog_entries 投影及定向详情/系列/人物查询；写事务只维护受影响数据。
- 实现首页、普通浏览、未匹配、收藏、续播和全局最近添加；最近添加统一取 20 项，不按库提前截断。
- 实现分组摘要分页、组内独立 keyset cursor、系列单集/人物作品分页、服务端稳定排序及子串搜索。
- 落实 catalog/favorites/progress revision 的不同依赖、TTL 与 cursor 失效规则，避免普通浏览被进度写入持续失效。
- 使用阶段 01 样本、EXPLAIN 和真实 HTTP 响应测量查询工作量、响应大小与延迟。

## Acceptance criteria

- [ ] 单详情只读取对应目标/资料，SQL 次数为小常数，不解析无关演职员；旧 attachMetadata 全表路径不再使用。
- [ ] 普通浏览不重复列已组织单集，未匹配却仍包含无资料的已组织文件；文件与电视剧独立收藏。
- [ ] 全局分类/搜索/收藏按媒体库分组；组顺序来自完整匹配集合的首项，不受已加载子页影响；空媒体库入口保留。
- [ ] 最近添加跨库统一、真实收录时间/新单集聚合/同时间稳定排序正确；续播按文件。
- [ ] 搜索命中单集文件名时可找到完整电视剧，季集计数不随搜索词变小；保留子串搜索而非静默换成分词。
- [ ] 分页默认 50、最大 100；cursor 查询条件/版本/TTL 校验明确，变更可恢复，无重复/遗漏的静态数据分页。
- [ ] 卡片 DTO 不含完整演职员、全季集或图片 BLOB；首页和 50 条列表响应符合 spec 的 256 KiB 目标。
- [ ] 热查询 p95、数据规模增长、query plan、行数和冷查询分别报告；不足处完成定位/优化，不伪报目标已满足。
- [ ] 投影更新失败和缓存到期仍保持正确回退及绑定/人物关系，相关集成和 race 测试通过。

## 验证与交接

运行 1,000/10,000/50,000 文件基准及查询集成测试，固定测试环境、次数和冷热条件。提交可复跑结果，不把上一轮功能测试耗时当请求性能。为任务 05 提供可直接消费的分页 DTO，不留前端重做全量聚合。
