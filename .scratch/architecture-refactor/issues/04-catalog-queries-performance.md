# 04：查询投影、分组分页与性能

Status: resolved
Blocked by: 02, 03

Parent: [全量重构技术方案](../spec.md)

## 目标

让读查询按资源和页工作，消除单详情的全库资料解析与前端全量聚合，同时保持最新的媒体库分组、最近添加、搜索和人物语义。

## 范围

- 实现轻量 catalog_entries 投影及定向详情/系列/人物查询；写事务只维护受影响数据。
- 实现首页、普通浏览、未匹配、收藏、续播和全局最近添加；最近添加统一取 20 项，不按库提前截断。
- 实现分组摘要分页、组内独立 keyset cursor、系列单集/人物作品分页、服务端稳定排序及子串搜索。
- 落实 catalog/favorites/progress revision 的不同依赖、TTL 与 cursor 失效规则，避免普通浏览被进度写入持续失效。
- 使用阶段 01 样本、EXPLAIN 和真实 HTTP 响应测量查询工作量、响应大小与延迟。

## Acceptance criteria

- [x] 单详情只读取对应目标/资料，SQL 次数为小常数，不解析无关演职员；旧 attachMetadata 全表路径不再使用。
- [x] 普通浏览不重复列已组织单集，未匹配却仍包含无资料的已组织文件；文件与电视剧独立收藏。
- [x] 全局分类/搜索/收藏按媒体库分组；组顺序来自完整匹配集合的首项，不受已加载子页影响；空媒体库入口保留。
- [x] 最近添加跨库统一、真实收录时间/新单集聚合/同时间稳定排序正确；续播按文件。
- [x] 搜索命中单集文件名时可找到完整电视剧，季集计数不随搜索词变小；保留子串搜索而非静默换成分词。
- [x] 分页默认 50、最大 100；cursor 查询条件/版本/TTL 校验明确，变更可恢复，无重复/遗漏的静态数据分页。
- [x] 卡片 DTO 不含完整演职员、全季集或图片 BLOB；首页和 50 条列表响应符合 spec 的 256 KiB 目标。
- [x] 热查询 p95、数据规模增长、query plan、行数和冷查询分别报告；不足处完成定位/优化，不伪报目标已满足。
- [x] 投影更新失败和缓存到期仍保持正确回退及绑定/人物关系，相关集成和 race 测试通过。

### 实现与验收

- 所有文件（含已组织单集）/电视剧都有轻量投影；普通浏览折叠单集，未匹配保留原始文件；文件/电视剧独立收藏，续播始终按文件。
- 新 runtime 接入首页、全局分组、组内列表、全局最近添加、文件/电视剧详情、季/单集分页及收藏 HTTP。空库首页入口、完整匹配集合决定组序、跨库统一 top-20、首次收录时间与新单集推进、同时间稳定顺序均有真实 SQLite/HTTP 测试。
- NFC/Unicode case fold 子串搜索与锁定的中文/数字 collation；搜索单集文件名仍返回完整电视剧计数。排序/聚合完全在服务端，不要求 05 再拉全库整理。
- 默认 50、最大 100 的有界 DTO/签名 keyset cursor；校验查询、资源、页大小、revision、5 分钟上限及相关资料最近到期。普通浏览不因收藏/进度写入反复失效，收藏/续播各自依赖对应 revision；过期 `409 CURSOR_STALE` 可重新取首页。
- 文件详情固定最多 7 条 store SELECT（HTTP 会话另 1 条），只解析该目标最多 150 条演职员；卡片无演职员/全季集/图片 BLOB/绝对路径。人物作品按当前绑定去重、优先可用代表，并批量装配卡片/该页人物关系。
- 标题写事务同步生成搜索/排序键；删除只更新被删文件及其电视剧，不重建无关条目。真实 projection fault 回滚、资料到期立即本地回退且保留手动选择/人物关系、并发家庭状态写入均通过。
- 新增 8 个 store 查询/回归测试、3 个 HTTP/cursor 测试及 1 个可选真实 HTTP 性能入口。修正旧人物分页测试的依赖：普通人物作品不再因收藏写入失效，保留跨资源/任务 cursor 隔离断言。

### 性能与诊断

环境：macOS arm64，Apple M5 Pro / 18 CPU / 48 GiB，Go 1.25.12、Node 26.7.0。每档 10 库，1,000/10,000/50,000 文件，1,000/5,000/5,000 目标，各 100 演员 + 50 导演；每 endpoint 30 次热请求。最终测量与独立旧 UI/race 验证部分重叠，报告注明，不冒充独占资源的生产 SLA。

| 文件数 | 首页 p95 | 50 条列表 p95 | 单文件详情 p95 | 50 部人物作品 p95 |
| --- | ---: | ---: | ---: | ---: |
| 1000 | 6.410 ms | 1.993 ms | 1.329 ms | 4.792 ms |
| 10000 | 22.950 ms | 3.893 ms | 1.017 ms | 18.234 ms |
| 50000 | 101.035 ms | 8.182 ms | 1.078 ms | 17.817 ms |

50,000 文件档：首页 54,471 B、50 条列表 25,482 B、人物 50 部作品 27,900 B。所有测量场景热 p95 < 200 ms，首页/50 条列表 < 256 KiB。首次重开 SQLite 请求单独报告，未清 OS 页缓存，不称为冷盘；EXPLAIN、实际 SQL、匹配/返回行数保存在 JSON，未测 SQLite VM 访问行数不伪报。

复测曾暴露批量资料刷新后 10,000 文件“最近添加”约 1 秒的真实退化：独立 SQLite 可重现，单独 `ANALYZE` 无效。去掉事件排序 selection 不需要的资料/家庭状态 JOIN，避免依赖 SQLite 自动消除无用 JOIN；相同样本恢复约 7 ms，首页约 22 ms。最终上表为修复后的完整 HTTP 实测，回归断言和刷新型性能样本已保留，临时诊断代码已移除。
