## 1. 结论与范围

采用 **保留产品能力、重建内部结构的一次性不兼容重构**：继续使用 Go、React/TypeScript、SQLite、单应用部署；围绕媒体编目、影片资料、播放与文件操作建立职责明确的 module，统一查询与前端状态模型，移除历次兼容层。不是换框架、拆微服务，也不是按文件长度机械拆分。

优先解决四个问题：

1. **查询随全库膨胀**：详情也加载全部资料关联，首页把全部文件、季集和完整资料下发浏览器，再做筛选、聚合和排序。
2. **并发控制粒度过大或缺少提交约束**：资料获取持全局锁等待网络，配置保存因此返回“忙”；扫描移除目标与资料写入又不共享同一有效性约束。
3. **身份与缓存模型被历史实现绑架**：TMDB 字段侵入通用模型；MetaTube 为适配整数 ID 而在搜索中写本地映射；资料关联、有效缓存、人物索引、图片缓存混杂。
4. **维护知识分散**：`App` 同时负责 HTTP、SQL、文件安全、后台任务和上游；前端分散维护请求、全局事件、URL、轮询和覆盖式样式。

### 1.1 “不考虑历史兼容性”的明确含义

- 不兼容旧数据库、旧 HTTP 字段/别名、旧前端资源、旧资料源环境变量及旧升级脚本；不双写、不维护双套运行路径。
- 新版本从**新的空应用数据目录**初始化。账号、媒体库配置、资料源设置须重新设置；重新扫描后生成新媒体 ID。旧匹配、收藏、观看进度和串流地址不导入。
- 这不等于取消新版本内部的持久化：新版本正常重启必须保持账号、配置、媒体身份、手动匹配、进度、收藏和串流密钥。
- 检测到非空旧库或不支持的 schema 时**拒绝启动，不自动清空、覆盖、迁移或重新生成密钥**。正式切换与弃用旧状态属于后续部署动作，不在本轮授权范围内。
- 重构不授权删除、修改、移动用户媒体。所有验证使用隔离临时数据。

### 1.2 明确不做

不新增转码、下载器、上传、SMB/NFS 管理、实时/定时扫描、多用户、个人进度、推荐算法、批量删除、回收站、NFO、外部完整作品年表或串流链接自动过期。不改变现有 Emby 风格产品方向，不以重构名义重新设计整套视觉稿。

### 2.3 易混语义固定下来

- **未组织 ≠ 未匹配 ≠ 不可播放**。已组织单集无有效资料时仍属于未匹配媒体；资料故障不能阻断打开本地文件。
- **浏览聚合 ≠ 文件合并**。普通列表和最近添加把已组织单集聚合为电视剧；播放、进度、删除永远定位具体媒体文件；收藏页允许文件收藏与整部电视剧收藏同时出现。
- **文件版本 ≠ 作品身份**。仍使用目录身份、相对路径和设备/inode/大小/mtime 等元数据检测文件版本，不声称做全视频内容哈希。同路径换文件不得继承旧 ID 或旧串流能力。
- **资料选择 ≠ 有效资料快照**。手动选择可以在缓存到期、来源禁用或来源配置失效时继续存在，但到期资料不能继续展示为有效。
- **删除即时状态 ≠ 扫描清理**。确认删除后先标记文件已删除；下一次完整成功扫描再清理该文件及依赖。保留这个用户可观察的行为，不把重构变成删除语义变更。

## 4. 总体架构：有清晰 seam 的模块化单体

### 4.1 目标目录与职责

```text
cmd/reelnest/                 # 参数、信号、进程启动
internal/
  app/                       # 仅依赖装配、生命周期
  model/                     # 跨 module 的少量纯值类型/错误码；无 I/O
  identity/                  # 家庭账号、会话、登录限流
  catalog/                   # 媒体库、扫描、组织、浏览、收藏
  metadata/                  # 设置、匹配、任务、快照、人物、图片
    providers/               # TMDB / TVDB / MetaTube adapters + 受控 HTTP
  playback/                  # 播放预检、进度、串流、字幕、两步删除
  mediafs/                   # 根目录与文件句柄、安全遍历、身份、精确 unlink
  store/                     # SQLite schema、查询、事务性提交、读投影
  transport/http/            # HTTP DTO、路由、鉴权接入、错误/状态码
  web/                       # 已构建静态资源嵌入
api/openapi.yaml             # 新版 HTTP 契约
web/src/
  app/                       # Router、页面壳、会话、QueryClient
  features/{catalog,libraries,metadata,people,playback}/
  shared/{api,ui,styles}/
  generated/                 # 契约生成类型；禁止手写
```

- 依赖方向：`app → transport + 各业务 module`；`transport → 业务 module`；业务 module 使用 `store/mediafs/model`。`store` 不反向调用业务，provider adapter 不访问数据库或 HTTP handler。
- `store` 是一个有事务深度的 SQLite module，不是为每张表建立一层 Repository。它暴露 `CommitScan`、`CommitMatch`、`MarkFileDeleted` 等用例级操作；不向所有调用者泄露 `*sql.Tx`、任意 SQL 或表名。
- 只有真实变化的位置建立 seam：三种 provider adapter、受控文件操作、时间与外部 HTTP。数据库测试直接使用真实临时 SQLite，不为了 mock 造通用仓储框架。
- `mediafs` 返回已校验、可关闭的文件能力，不返回“验证过的路径”让调用者再打开；文件名解析是纯函数，可以无 I/O 测试。
- 模块化不以文件行数作为验收：改一种资料源协议应局限于 adapter；改聚合语义应局限于 catalog 查询及对应测试；改 HTTP 不能迫使文件安全逻辑认识 `http.ResponseWriter`。

### 4.2 持久化与进程生命周期

- 保留 SQLite WAL。一条写连接串行短事务，独立只读连接池初始上限 4；每条连接正确设置外键/超时。先通过并发和锁等待基准再调整，不盲目增加写连接。
- 单一 `schema.sql` 初始化空库，以明确的 schema 标识/版本判定可运行性。禁止逐个功能 `initializeX()` 中散布 `ALTER TABLE`、旧数据猜测或兼容回填。
- 网络、文件遍历、图片下载不放进数据库事务。提交失败全部回滚；批量查询关闭 rows 后才进入其他事务，不依赖“单连接时碰巧不死锁”。
- worker 数量有界，关闭过程依次停止接受任务、取消可取消任务、等待已开始的删除后核对、关闭 DB。任务提交和 worker 停止受同一生命周期控制，禁止关闭后继续 `WaitGroup.Add`。
- 单个 DATA_DIR 只允许一个服务进程使用；启动取得进程锁，避免多个进程各自持有无效的内存互斥。

## 5. 数据模型与唯一真源

以下名称是实现模型，不替换 `CONTEXT.md` 的领域词汇；本次评审不修改领域词汇或既有 ADR。

### 5.1 本地媒体

| 数据 | 设计/约束 |
| --- | --- |
| `libraries` | 将现有媒体目录配置与其一对一媒体库资源存一行：ID、名称、根路径/根身份、类型、配置 revision、资料策略 revision；不再复制一套 1:1 实体 |
| `library_sources` | `(library_id, source, priority)`，外键及排序唯一约束；空集合代表禁用自动获取 |
| `media_files` | 独立文件 ID、library_id、相对路径、版本指纹、大小、修改时间、真实收录时间、状态；同路径同版本唯一 |
| `series` / `file_organization` | 同库本地 title_key 唯一；一个文件至多一个季集位置；不同文件可处于同一季集；季与单集仍为查询层级，无需只存编号的空实体表 |
| `watch_progress` | media_file_id 外键；位置/时长/完成标记/更新时间；有限数值验证 |
| `media_favorites` / `series_favorites` | 保留两个有真实外键的小表，不为形式统一改为无约束多态 ID |
| `scan_runs` / `scan_entries` | 一次扫描的状态和分批暂存清单；只有发布事务能改变有效索引 |

### 5.2 资料选择、快照、人物与图片

- `metadata_subjects`：统一**可匹配的本地目标**。记录 expected_kind 及唯一的 `media_file_id` 或 `series_id`，CHECK 保证二选一，两者都是真实外键并级联清理。电影文件、未组织电视剧文件有自己的目标；已组织单集读取所属电视剧的目标。
- `metadata_bindings`：以 subject_id 为外键，保存选定 remote_title_id、automatic/manual、revision 和最近尝试结果。绑定不随快照到期删除。扫描组织变化时事务性删除旧目标，不能把未组织文件的手动匹配扩散给整部电视剧。
- `remote_titles`：稳定的外部作品身份，唯一键为 `(catalog_id, namespace, kind, remote_id)`；remote_id 一律字符串，不能解析、哈希成整数或转换大小写。namespace 对 TMDB/TVDB 固定，对 MetaTube 保留上游 provider（按其现有大小写规则规范化）。本地 surrogate ID 可统一用于外键/URL，但不是为某个 provider 提供整数兼容。
- `provider_catalogs`：外部作品目录空间。TMDB/TVDB 使用固定空间；MetaTube 规范化服务地址变化时创建新空间。Token 轮换不改变空间。旧空间可继续标识既有手动选择，但不能用新服务解释旧 remote_id。
- `metadata_snapshots`：remote_title_id 对应当前有效资料，结构化存标题、原名、编号、年份、简介、来源页、获取/失效时间、图片和演职员状态、revision。**稳定身份与有时效的内容分表**，到期删除内容不破坏手动选择。
- `title_credits`：与快照同事务写入的结构化演员/导演关系，按 `(catalog_id, person_key, remote_title_id)` 建索引。姓名/角色/图片引用由此读取，不同时把完整演职员 JSON 当另一份真源。角色数组可局部 JSON 存储，但不再扫全库 payload。
- 没有可靠人物 ID 时，person_key 限定当前作品范围；有 ID 时仍必须带来源目录空间。人物页只从**当前绑定、有效快照、有本地目标**的关系查询。同一外部作品的多个本地版本去重，优先可用文件；电视剧不重复列单集。
- `assets`：统一 Primary、Thumb、Backdrop、人物照片的受控引用、字节 BLOB、MIME、expires_at、retry_at、revision。关系指向当前快照/人物；图片字节继续放 SQLite，暂不引入磁盘对象存储及额外 GC 协议。查询卡片绝不加载 BLOB。

正常运行唯一写入口负责快照、演职员、图片引用与读投影的一致性。删除旧 `metadata_people_state`、payload 变更触发器和“有人直接改 JSON 后启动时修复”机制；**外部直接修改应用数据库不是受支持 interface**。开发排障需要重建时使用明确的离线校验/重建命令，而不是每次启动修复未知结构。

### 5.3 读投影

`catalog_entries` 是可重建的轻量读投影：每个文件、每部电视剧各一行，包含本地显示/搜索键、媒体库、文件/系列类型、季集归属、计数、收录时间和当前资料引用。真实文件及关联表仍是真源。

- 扫描、匹配、删除在各自提交事务内更新受影响条目及 `catalog_revision`；收藏/进度分别维护 `favorites_revision` / `progress_revision` 并可索引 JOIN，避免无收益的字段复制。普通浏览 cursor 不因每 10 秒保存进度而失效，收藏/续播查询才加入各自 revision。
- 所有有效资料查询显式判断 `expires_at > now`，不能依赖清理任务准时运行。过期立即使用本地标题/占位图，人物与图片遵循相同有效性约束。
- 只对命中的一页/一个详情装配资料；卡片没有完整演职员、全部单集、绝对源路径或图片字节。
- 建立 library、最近添加、收藏时间、继续观看时间、series/season/episode、资料绑定、人物作品查找所需索引。用 `EXPLAIN QUERY PLAN` 验证实际查询，不以“加了索引”代替证明。

### 5.4 状态转换与恢复

| 对象 | 状态与恢复规则 |
| --- | --- |
| 扫描 | `queued → running → completed/failed/interrupted`；启动发现未终结任务转 interrupted，仅手动重试；创建媒体库的首次 queued 由本次运行调度 |
| 资料任务 | `queued → running → succeeded/failed/superseded`；启动恢复可重试的非破坏性任务；领取和完成均比较 requested generation，旧 worker 不得清掉后来入队的工作 |
| 资料选择 | 无绑定、automatic、manual；手动选择成功才改绑定；刷新失败只记尝试结果，不能清空选择或切回 automatic |
| 资料快照 | absent、fresh、expired 独立于选择；fresh 允许演职员/图片部分失败；读取时按 TTL 判定，不靠任务状态猜测 |
| 文件 | 已收录可用 → 删除后不可用 → 成功扫描清理；外部缺失/替换由打开时返回实际错误，不在失败扫描中批量改状态 |
| 图片 | missing → ready 或 cooling；取消/配置过期不等于上游失败；引用变化时旧 ready 不可套用到新引用 |

扫描、资料任务和图片缓存使用各自的小状态机，不扩展为通用工作流引擎。任务的自动重试次数初始上限 3 次（每个请求 generation），遵守来源冷却；耗尽后等待显式刷新或新配置触发，不无限重试。

## 6. 三条关键流程

### 6.1 扫描：完整发布，不扩大文件风险

1. 创建媒体库和初次 `scan_run` 在同一事务提交；重扫只接受同库一个 queued/running 任务。
2. 最多 2 个扫描 worker。取得**该媒体库**的变更锁后，通过 `mediafs` 打开根句柄并核对根身份；遍历每批最多 256 条写入 staging，内存不保留全目录 `[]FileInfo`。遍历中的目录项也分批读取。
3. 任意读取失败、目录替换或取消，标记 failed/interrupted，丢弃 staging；有效媒体索引和家庭状态完全不变。
4. 遍历结束再次核对根身份；在一个事务中合并未变文件、插入新版本、组织季集、移除未发现文件、清理空电视剧及外键依赖、更新投影、排队受影响的资料目标，并标记 completed。
5. 应用重启将未完成扫描标记 interrupted，不自动把不完整 staging 发布，也不自动重新扫描媒体目录。

同库扫描与删除串行，以免旧快照让已删除文件复活；不同库允许并行。删除遇到同库扫描立即返回可解释的 `LIBRARY_BUSY`，而不是无期限等待到确认过期。读取和进度保存不持此锁。保留现有外部文件系统并发限制：应用锁不能阻止宿主机/NAS 上其他程序改文件。

### 6.2 资料：先取快照、无锁 I/O、条件提交

每个任务携带 `(subject_id, subject_revision, binding_revision, policy_revision, provider_revisions, catalog_id)`。subject revision 表示本地目标变化，binding revision 表示资料选择变化；provider_revisions 记录本次实际使用的来源配置版本（自动回退可涉及多个来源）。

1. 短读取得本地目标、手动选择、目录策略和不可变 provider 配置快照；不因取得快照持锁到网络结束。
2. 按来源优先级执行，每源最多 20 秒、单目标最多 65 秒。无唯一可靠结果才回退；结果不完整时不能宣称唯一。MetaTube 对电视剧直接报告不支持，不发无意义请求。
3. 短提交事务再次验证目标存在、未删除、类型未变，以及上述 revision/目录空间仍有效；成功才写绑定、快照、人物关系和投影。任何旧结果，包括**失败状态、补充图片、补充演职员**，都不能覆盖较新状态。
4. 版本不符标记 superseded，不写回旧结果；仍有需要时按最新版本重新排队。外键保证已被扫描移除的目标不能产生悬空绑定。
5. 手动选择使用相同流程并递增绑定 revision。候选包含其来源目录空间和读取时版本；保存前重新校验、获取并验证真实作品。失败保留原选择。

后台保留一个资料专用有界 worker pool（初始 2），`metadata_jobs` 按 subject_id 合并待办，保存状态/尝试版本/错误类别和 next_attempt_at。不用全库 wake 后逐个重做，也不建立通用 DAG/分布式队列。触发仅来自新增目标、相关设置变更、启动恢复和显式刷新；retry_at 到期只是允许已有任务重试，**不是定时媒体扫描或强制周期重匹配**。

来源配置保存只需短暂序列化“DB 提交 + registry 发布”，并用请求 revision 做乐观并发控制；不因背景网络慢返回配置忙。新请求取得新配置；旧在途请求允许有界结束但无权提交旧结果。目录策略变化只重评自动匹配，手动选择不被替换。

MetaTube 地址变化：不把旧 Token 带给新地址；旧手动选择保持原目录空间并标记需人工重选，已有未到期快照可读到原到期时间；不再向旧空间发新网络请求，不用新地址刷新旧标识。新自动匹配使用新空间。此规则同时用于图片和人物关联，不能只隔离标题。

### 6.3 删除：保留强安全实现，不承诺跨系统事务

- `mediafs` 集中 root containment、逐级非符号链接检查、同句柄读取、指纹/父目录校验、`unlinkat(flags=0)`；禁止简化为 `filepath.Join + os.Remove`。
- 预览仍是有时效、绑定目标路径/身份的确认材料，**不是授权凭证**；提交仍须家庭会话和二次确认。与串流签名使用不同域分隔。
- unlink 前取消可以退出；unlink 后即使 HTTP 断开，也用独立的有界上下文尝试索引核对并通知资料任务失效。
- 返回结构明确 `fileOutcome=deleted|not_deleted|unknown` 与 `indexOutcome=updated|pending`。已删除但 DB 失败不得返回可自动重试的普通失败；网络断开也不能推断“未删除”。
- 前端不得自动重试删除；遇到未知/部分成功提示核查并重新扫描。文件已删而索引未更新时，读取仍凭真实文件身份拒绝。
- 不承诺 POSIX 原子按 inode 条件删除；最后检查与 unlink 之间的外部恶意/并发替换风险仍需要部署者避免。已有打开句柄可能继续读取。

## 7. 资料源与图片 interface

### 7.1 Provider adapter

推荐稳定 interface 为：`Capabilities()`、`Search(ctx, query)`、`FetchTitle(ctx, ref)`、`FetchImage(ctx, imageRef)`。

- `SearchResult` 返回结构化候选和 complete 标记；`FetchTitle` 返回一个结构化 `TitleSnapshot`，而不是当前五元组，也不混入本地路由 URL。
- 支持类型、人物身份能力等由 Capabilities 表达。各 adapter 在内部完成基础资料/演职员/图片引用的协议组合；MetaTube 详情本来已完整时只取一次，不强制再次请求 credits/artwork。
- 单次标题获取允许部分演职员/图片引用失败，返回独立状态与有界重试时间；标题成功不被可选图片失败否定。优先使用有效缓存；只刷新到期或失败到重试时间的部分，不借“补齐”延长原 TTL。
- adapter 不写本地 ID 映射、不生成站内 URL、不访问 SQLite。公共来源固定上游；MetaTube 仅访问管理员显式配置的 HTTP/HTTPS origin/前缀，不跟随重定向或响应中的任意 URL。
- API 凭据与图片 HTTP 通道分离，图片不携带 API Token。保留响应体上限、来源独立冷却、`Retry-After`、超时和错误脱敏；不通过并发池绕过来源限流。

### 7.2 统一图片缓存

- Primary、Thumb、Backdrop、照片都走 `assets`；不再“海报随匹配同步下载，横图/照片另走两套缓存”。匹配先写安全引用，图片按需读取。
- 缓存键含目录空间、作品/人物身份、图片类型、引用版本；按**相同图片 key**合并未命中请求，不用全局单通道把不同图片串行化。
- 全局同时下载最多 4 个、每来源最多 2 个；API 与图片预算独立，但各自遵守上游限流。缓存命中不排队。
- 下载任务使用应用生命周期和 15 秒预算，等待者可单独取消；单个页面离开不能把共享缓存写成 24 小时失败。真实上游失败才记录退避（默认 24 小时）。
- 最大 5 MiB；检查 MIME 与内容签名，拒绝 SVG/HTML/重定向和超大响应。写入前校验引用/配置 revision 未变；不能把旧图片填入新资料。
- 有效期不超过所属资料及来源策略上限；到期不返回旧字节，不使用无限 stale-while-revalidate。仍保留来源署名和资料有效期展示，不重新解释上游许可。

## 8. 查询与 HTTP 契约

### 8.1 服务端决定语义，前端只展示

- `/api/home` 返回媒体库预览、继续观看、全局最近添加三类轻量资源；继续观看/最近添加各最多 20 项。媒体库入口本身可分页，空库不被内容 JOIN 吞掉。
- 普通浏览：电影文件 + 电视剧摘要 + 未组织电视剧文件；已组织单集不重复列出。
- 未匹配：返回没有有效资料的原始媒体文件，包含已组织单集，不用“未组织”代替此过滤。
- 收藏：文件收藏与系列收藏各自入列，按收藏时间排序。继续观看始终按文件、不按作品折叠。
- 最近添加：按文件首次成功收录时间；电视剧为现存单集文件最大收录时间；全局统一排序，时间相同按稳定 entry key 排序，不先对各库截断再合并。
- 搜索保持文件名/本地电视剧名/有效资料标题的大小写无关子串语义；匹配单集文件名可命中完整电视剧摘要，其季集计数始终是整部作品计数，不随搜索词改变。
- 标题排序统一在服务端生成中文/数字友好的稳定排序键，浏览器不再用另一套规则重排服务器页。排序算法和归一化版本由依赖锁定并测试。
- 子串查询可能扫描轻量搜索列，**不谎称普通 B-tree 能优化任意 `%q%`**；先基准验证，未达目标再评估专用子串索引，不默认引入搜索服务。

### 8.2 分页和分组

- 列表默认 50 条，最大 100 条；系列单集和人物作品同样分页。媒体文件卡、系列卡、人物作品卡使用不同 DTO，详情按需加载。
- 全局分类/搜索/收藏使用“媒体库分组摘要页 + 每组独立 entries cursor”，避免全局分页把组拆散、丢掉后面媒体库；分组按其完整匹配集合中首项的排序键、媒体库 ID 稳定排序，不按当前加载的子页猜测组顺序。最近添加使用一个不分组 cursor。选择单库后只返回该库的数据。
- keyset cursor 携带查询摘要、排序键、稳定 ID、catalog revision、有效期；变更导致失效时返回 `CURSOR_STALE` 并重新加载，不承诺跨变更的数据库快照。
- cursor 有效期至多 5 分钟，且不跨越相关有效资料的最近到期点；返回旧页时仍重新核验 TTL，过期使 cursor 失效。读取 revision、条目和计数在同一只读事务完成。
- 列表响应体及前端已渲染卡片数必须有界；“载入更多”不能无限保留全部 DOM，可使用页面切换/窗口化策略。

### 8.3 新契约能力表

下表是实施的 interface，不为旧路由提供 alias；完整字段/状态在阶段 1 写入 OpenAPI，生成 TypeScript 类型。Go handler 使用显式 DTO，由契约测试验证，不从数据库行结构直接序列化。

| 能力 | 新 HTTP interface |
| --- | --- |
| 家庭身份 | `POST /api/login`、`POST /api/logout`、`GET /api/session` |
| 媒体库 | `GET/POST /api/libraries`、`PATCH /api/libraries/{id}`（revision + 名称/资料源顺序） |
| 扫描 | `POST /api/libraries/{id}/scans`、`GET /api/scans/{id}` |
| 浏览 | `GET /api/home`、`GET /api/catalog/groups`、`GET /api/catalog` |
| 文件/电视剧 | `GET /api/media/{id}`、`GET /api/series/{id}`、`GET /api/series/{id}/seasons/{number}/episodes` |
| 收藏 | `PUT /api/favorites/{media|series}/{id}`，目标真实存在，设置幂等 |
| 匹配 | `GET /api/metadata/subjects/{id}/candidates`、`PUT /api/metadata/subjects/{id}/selection`（expected revision + typed ref） |
| 后台资料 | `POST /api/metadata/refresh`（可指定媒体库）、`GET /api/metadata/status`（任务摘要和可分页失败目标） |
| 设置 | `GET /api/settings/metadata`、`PATCH /api/settings/metadata/{source}`（revision） |
| 人物/图片 | `GET /api/people/{id}`、`GET /api/people/{id}/works`、`GET/HEAD /api/assets/{id}/content` |
| 播放/进度 | `GET /api/media/{id}/playback`、`GET/HEAD /api/media/{id}/content`、`GET/PUT /api/media/{id}/progress` |
| 串流/字幕 | `POST /api/media/{id}/stream-link`、`GET/HEAD /stream/{id}`；媒体文件下字幕列表/内容 interface |
| 删除 | `POST /api/media/{id}/deletion-preview`、`POST /api/media/{id}/delete`，独立于通用资源删除 |

统一约定：

- ID 在 JSON 中全部为字符串；source 固定 `tmdb|tvdb|metatube`，显示名另给；时间统一 Unix 毫秒，未发生为 null；不保留 `tmdbId`、整数 `sourceId` 兼容字段或重复的 `matched` 布尔真源。
- 缓存状态、匹配方式、任务状态分别用明确枚举。HTTP 错误为 `{error:{code,message,retryable,requestId}}`；冲突区分版本变化、扫描忙、cursor 失效，不能全部靠中文字符串识别。
- JSON 体默认最多 16 KiB，拒绝未知字段、无效枚举和尾随 JSON；设置字段各自保留长度限制。GET 查询有长度/页数上限。
- 写接口同源校验和家庭会话保护；串流只认文件凭证，不能借它调用图片、字幕、收藏、进度或管理。Range 错误允许标准 HTTP 内容响应，不强制伪装 JSON。
- `healthz` 不泄露配置；健康检查区分进程存活与 DB/worker 就绪。静态资源更新与后端契约整体发布，不维护跨版本客户端。

## 9. 前端重构

### 9.1 状态分工

- 引入 React Router 统一页面/URL 状态，TanStack Query 统一服务端状态。两个依赖对应当前真实重复实现，不再自行维护 Router 或全局事件缓存框架。
- 媒体库范围、分类、搜索词、排序、视图、季、分页状态由 URL 决定；返回/刷新可复现。播放器弹窗、确认框、输入草稿为局部状态；表单草稿不能被后台刷新重置。
- query key 包含资源/媒体库/过滤/分页条件；所有查询接受 AbortSignal。变更成功后精确更新或 invalidate 相关 keys，不再发 `window.dispatchEvent("metadata-updated")`。
- 收藏使用服务端确认结果更新；并发刷新不可回滚已确认状态。资料变更只失效受影响的详情、人物和列表，避免全站反复拉取全部资料。
- 一个任务状态订阅位置：运行期间 1–2 秒轮询，空闲停止快速轮询，仅在前台恢复/定期低频检查（30 秒）或操作完成时更新；隐藏页面暂停。初次状态读取不能额外触发一次全库加载。
- 统一请求超时、HTTP/非 JSON 错误、401 跳转、取消不提示失败。设置版本冲突保留草稿并允许重新加载后重试，绝不静默覆盖他人配置。

### 9.2 播放器独立状态机

提取播放器控制与进度写入 hook，状态包括 checking、ready、playing、paused、blocked、failed、closing。UI module 不负责请求排队细节。

- 先恢复进度后 play；保留原生 ended 语义、10 秒周期及暂停/seek/隐藏时保存。
- 同一播放器最多一个在途进度写入和一个待提交最新快照，合并多次 seek/pause，不建立无限 Promise 队列；不改变跨浏览器“最后收到的有效更新生效”的规则。
- 关闭时暂停、尽力提交，设置可见且有界的保存等待（目标最多 3 秒）；超时允许退出并提示未确认保存，不把进度失败困在不可关闭弹窗。离开页仅 best-effort，不宣称必达。
- 外部播放器 URL 编码、复制失败兜底、字幕 Abort/Blob 释放分别测试；不以协议唤起证明实机播放成功。

### 9.3 样式与展示

保留设计 token、Emby 风格卡片比例和桌面/窄屏布局；只把 reset/token 放全局，页面/卡片/弹窗使用 CSS Modules。页面壳通过明确 variant 控制首页/详情/管理，不靠三份文件反复覆盖 `.sidebar/.content/.app-header`。统一卡片和收藏入口，删除未引用的 `SeriesCard` 及旧样式时先用引用/覆盖率核验。

## 10. 可观测性与安全边界

- 结构化日志记录 requestId、任务 ID、subject/library ID、错误类别、阶段耗时和是否版本失效；不记录凭据、响应原文、串流查询参数或用户媒体内容。
- 测量查询耗时/行数/响应大小、扫描收集/发布耗时、资料队列等待/来源耗时、图片命中/合并/失败、DB 锁等待。先使用日志与测试计数，不新增观测平台。
- 凭据继续 AES-256-GCM，密钥独立 0600 文件，密文与配置来源/地址绑定；备份包含密钥和 DB 时仍是敏感材料。密钥丢失拒绝启动，不生成新密钥“修复”。
- 文件平台能力封装在 mediafs 的 Linux/macOS adapter；Windows 服务端不在当前交付承诺内。Windows 外部播放器是客户端能力，不能与服务端平台支持混为一谈。
- MetaTube 明确配置的内网 HTTP 服务仍允许；不把“防任意 URL 代理”错误实现为禁止所有内网来源。服务配置权属于家庭共享账号，没有新角色体系。

## 11. 性能与验证计划

### 11.1 量化工程目标（不是已达到结果）

目标数据集：10 个媒体库、50,000 个文件、5,000 个资料目标、每目标最多 100 演员/50 导演；另用 1,000/10,000 文件小集观察增长曲线。使用合成内容和临时 DB，记录硬件、Go/Node 版本、冷热缓存、样本次数；现有正常功能测试通过不等于达到这些目标。

| 场景 | 目标/确定性门槛 |
| --- | --- |
| 单文件详情 | 只查目标关联；SQL 次数固定在小常数（目标 ≤ 8）；不解析任何无关作品的完整演职员 |
| 首页/列表 | 卡片数量有界；首页/50 条列表 JSON ≤ 256 KiB（不含图片）；响应不带全季集和全演职员 |
| 热查询 | 本机基准首页、列表首屏、详情、50 条人物作品 p95 ≤ 200 ms；冷查询单独报告，不混进热结果 |
| 资料源变慢 | 上游阻塞 20 秒时，本地查询、进度、配置保存不等待该网络；配置保存本机 p95 ≤ 200 ms（无其他 DB 故障时） |
| 图片 | 同 key 并发只下载一次；不同图片最多 4 个全局/2 个同源；缓存命中不等待慢图 |
| 扫描 | 50,000 文件时不持完整内存文件清单；取消/失败对已发布索引零改动；不同库不共享遍历锁 |
| 前端 | 初屏 DOM 与 page size 成比例；无全库数据数组；空闲不持续每秒拉接口；返回/重试无旧响应覆盖 |

不把这些目标写成未经测量的 SLA。若基准不达标，先记录 query plan/CPU/IO/响应大小找到主因，再决定是否增加搜索索引、改变连接数或缓存存放方式。

## 13. 评审决策与风险

以下取舍已随本方案由用户于 2026-10-02 评审通过；后续若改变，应先修订方案，不静默偏离：

- **接受不导入历史应用状态**，用新空目录换取删除兼容链；若之后要求保留旧进度/收藏，需要另立一次性离线转换需求，不能偷偷恢复运行时兼容。
- **接受少量基础库**：Router、Query、契约类型生成和前端 unit test；收益是移除真实重复逻辑，不引入新的服务依赖。
- **接受资料来源目录空间与版本提交模型**：比一个全局 mutex 复杂，但复杂度集中于资料 module，并解决已有来源/设置/手动选择的真实竞态。
- **保守保留文件删除风险约定**：抽象提升复用性，不提升为 OS 无法提供的原子保障。
- **重写查询但不更换搜索语义**：暂不使用 FTS 分词替代子串搜索；性能不足先测量再扩展。

方案与评审阶段仅维护方案、审计及实施任务文档；不修改 CONTEXT/既有 ADR、不变更现行 HTTP 文档，以免把未来态写成已交付事实。实施完成时再把 README 和 `docs/api.md` 收敛为当前态，历史验证记录继续保留。
