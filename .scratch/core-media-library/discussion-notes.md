## 已确认

- 面向个人与家庭，在局域网内通过浏览器浏览和播放媒体。
- 媒体来自本机或 NAS 上已有的电影、电视剧文件。
- 优先打通：添加媒体目录 → 整理海报墙 → 播放 → 下次继续看。
- 仅实现核心功能，不以完整复刻 Emby 为目标。
- 浏览器仅直接播放其支持的媒体，第一版不做服务器实时转码；不兼容时明确提示。
- 支持串流到观看者设备上的外部播放器，目标包括 IINA 和 PotPlayer。
- 网站仅记录浏览器内的观看进度；外部播放器不向网站同步观看进度或已看状态。
- 第一版仅设一个家庭共享账号，媒体库和观看进度共用，不做多用户或权限分级。
- 外部播放器在兼容环境提供一键唤起，同时始终提供复制串流地址的入口，供用户手动粘贴到播放器打开。
- 删除源文件属于核心范围：删除磁盘或 NAS 上的实际视频文件，而非仅移除媒体库记录；操作前展示目标文件路径，并二次确认。
- 删除限定为单个视频文件的永久删除；不做回收站或批量删除，不连带删除字幕、海报或文件夹，确认框提示“本系统无法恢复”。
- 第一版单机 Docker 部署，通过挂载目录接入媒体；NAS 共享由宿主机预先挂载，需要删除的目录授予相应写权限。
- 不内置 SMB/NFS 配置管理，不提供媒体上传、片源下载、改名或移动功能。
- 添加媒体目录后自动扫描一次，之后由用户手动重新扫描；第一版不做实时文件监听或定时扫描。
- 海报与影片资料首版仅从 TMDB 获取，由部署者配置自己的 API 凭据，中文优先，暂不导入本地 NFO。
- 未配置凭据、联网失败或无法匹配时，仍按文件名和占位图展示并允许播放；认错影片时允许手动重新匹配。
- 媒体库按电影、电视剧分类；电视剧按“剧 → 季 → 集”展示，通过文件名中的 `S01E01` 等季集编号识别单集。
- 首版一个视频文件对应一部电影或一集，不做多集合一或同一作品多个版本的合并；无法识别的文件保留为未匹配媒体，不强行归类。
- 网页使用家庭共享账号和密码登录；外部播放器使用不可猜测、只读、不过期的单文件串流链接，不能用于管理或删除。用户接受链接泄露后不会自动失效的边界。
- 网页支持同名外挂 UTF-8 SRT/VTT 字幕，可选择或关闭；SRT 仅转换字幕文本。不做内嵌字幕提取、ASS/SSA 特效或字幕烧录，外部播放器的外挂字幕由用户自行加载。

## 外部播放器技术事实

以下是已核实的能力与限制，不等同于已经确认的产品范围或验收结果。

- IINA 在 macOS 注册 `iina` 协议，支持 `iina://open?url=<编码后的媒体URL>`；需要观看设备安装应用，并允许浏览器打开应用。来源：[官方协议处理源码](https://github.com/iina/iina/blob/v1.4.4/iina/AppDelegate.swift)、[协议注册](https://github.com/iina/iina/blob/v1.4.4/iina/Info.plist)。
- IINA 的 mpv 后端支持 HTTP(S) 媒体；实际媒体格式和定位播放仍需验证。来源：[mpv 官方协议文档](https://mpv.io/manual/stable/#protocols)。
- 旧版 IINA 存在 URL 参数处理漏洞；兼容性方案应以已修复的 1.4.4 或更新版为基础，仅生成必要且受控的打开媒体参数。来源：[官方安全公告](https://github.com/iina/iina/security/advisories/GHSA-w5xh-98j7-jp5q)。
- PotPlayer 为 Windows 客户端，官方记录确认 HTTP 播放和定位播放能力。来源：[官方产品页](https://potplayer.tv/?lang=en)、[官方更新记录](https://t1.kakaocdn.net/potplayer/PotPlayer/v4/Update2/UpdateEng.html)。
- 社区实现使用 `potplayer://<媒体URL>`，但尚未查到官方承诺各安装方式都会注册此协议。不能保证所有 Windows 设备免配置一键唤起，需要在目标环境验证。社区证据：[AList 实现](https://github.com/alist-org/alist-web/blob/main/src/pages/home/previews/video_box.tsx)。
- 外部播放器独立于浏览器，不能假设继承浏览器的登录 Cookie；媒体地址必须能从观看设备访问，不能使用服务器自己的 localhost 或本地文件路径。

## 影片资料来源的技术事实

以下资料用于判断候选方案，不代表已经选择相应数据源或实现完整格式兼容。

- TMDB 提供电影、电视剧的搜索与详情接口，并支持按剧 ID、季号和集号查询单集。来源：[官方工作流](https://developer.themoviedb.org/docs/search-and-query-for-details)、[单集详情](https://developer.themoviedb.org/reference/tv-episode-details)。
- TMDB 需要应用 API 凭据，可由部署者配置自己的 API Read Access Token。来源：[应用认证](https://developer.themoviedb.org/docs/authentication-application)。
- TMDB 支持 `zh-CN` 语言偏好，但不保证所有条目都有完整中文资料；图片地址需结合配置中的基址、尺寸与图片路径。来源：[语言机制](https://developer.themoviedb.org/docs/languages)、[图片地址](https://developer.themoviedb.org/docs/image-basics)。
- TMDB 非商业使用需遵守署名要求；API 条款限制所获信息缓存不得超过六个月，不能承诺永久保存其离线资料。来源：[FAQ](https://developer.themoviedb.org/docs/faq)、[正式条款](https://www.themoviedb.org/documentation/api/terms-of-use)。
- 尚未验证部署者实际网络到 TMDB API 与图片服务的可用性，文档可访问不等于目标环境可访问。
- Kodi 的 NFO 和本地海报是一条可行的离线资料来源，但存在电影、整部剧、单集及不同 NFO 变体，不能承诺任意 NFO 均可导入；单集文件命名识别仍需单独设计。来源：[NFO 总览](https://kodi.wiki/view/NFO_files)、[电影规范](https://kodi.wiki/view/NFO_files/Movies)、[单集规范](https://kodi.wiki/view/NFO_files/Episodes)、[本地电影海报](https://kodi.wiki/view/Movie_artwork)。

## 字幕技术事实

- HTML video 的外挂文本字幕以 WebVTT 为实用基线；SRT 需要转换为合法 WebVTT 或另外解析，不能仅改扩展名。来源：[HTML track 标准](https://html.spec.whatwg.org/multipage/media.html#the-track-element)、[WebVTT 标准](https://www.w3.org/TR/webvtt1/)。
- 单独处理字幕文本不要求解码或重编码视频，因此不与“不做服务器视频转码”冲突。字幕烧录则属于另一条处理视频帧的路径。来源：[FFmpeg 转码说明](https://ffmpeg.org/ffmpeg.html#Transcoding)。
- 浏览器只暴露其识别和支持的内嵌字幕；不能承诺任意容器中的字幕或完整 ASS/SSA 特效。来源：[内嵌字幕标准](https://html.spec.whatwg.org/multipage/media.html#sourcing-in-band-text-tracks)、[WebVTT 标准](https://www.w3.org/TR/webvtt1/)。
- 尚无已核实的官方依据保证 IINA/PotPlayer 通过 HTTP 播放视频时会自动发现服务器上的同名外挂字幕，不能将其当作已具备能力。

## 字幕范围

用户已确认：网页播放器支持与视频同目录、按视频文件名匹配的 UTF-8 外挂 SRT/VTT 字幕，可选择或关闭；SRT 仅转换字幕文本，不转码视频。
第一版不做内嵌字幕提取、ASS/SSA 特效或字幕烧录；外部播放器的外挂字幕由用户自行加载，不承诺自动发现或自动传递服务器上的字幕。
