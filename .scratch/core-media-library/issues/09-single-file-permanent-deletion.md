# 09: 安全地永久删除单个源文件

**What to build:** 家庭成员从单个媒体文件详情发起删除，核对目标路径并二次确认后，永久删除磁盘或 NAS 上的该视频；取消不删除，失败显示真实原因，媒体库反映实际文件结果。

**Blocked by:** 02（媒体目录扫描与基础媒体库浏览）

**Status:** ready-for-agent

**Parent:** [核心家庭媒体管理系统](/Users/bytedance/workspace/reel-nest/.scratch/core-media-library/spec.md)

**User stories:** 46, 47, 48, 49, 50, 51, 52, 53, 54, 56

## 范围与边界

严格遵循 ADR 0001 与 ADR 0002。本项按媒体文件身份操作，因此不依赖电视剧层级、TMDB 或播放器；不得演变为仅移出媒体库、回收站或批量删除功能。

## Acceptance criteria

- [ ] 首次点击删除不执行文件删除；确认界面展示实际目标视频路径，明确提示“本系统无法恢复”，提供独立确认和取消操作。
- [ ] 取消或关闭确认界面后，真实文件与媒体记录保持不变；确认后才允许尝试永久删除该媒体文件。
- [ ] 删除实际移除唯一选中的视频文件，不仅隐藏或移除媒体库记录；同目录字幕、海报、其他视频及目录全部保留，即使它们同名或与同一作品关联。
- [ ] 仅允许家庭共享账号执行删除；未登录、失效会话或仅携带非会话读取凭证的请求不能授权删除。不得把公开文件标识或未来串流地址当成管理权限。
- [ ] 请求只能指定受管理媒体文件，服务端校验其属于配置的媒体目录且确为预期视频；拒绝路径越界、目录/非视频目标及符号链接逃逸。
- [ ] 再次核对确认对象与实际删除目标；目标被替换、路径变化或无法确认仍是原文件时拒绝误删，不因沿用旧路径而删除另一个对象。
- [ ] 权限不足、挂载不可用、文件缺失或其他删除失败显示准确结果；未实际删除时不得提前清除记录或宣称删除成功，必要时将可用性与真实文件状态区分展示。
- [ ] 实际文件删除成功后媒体库不再把它作为可用视频展示；若随后索引更新失败，明确报告文件已删除但索引未更新，不谎称可恢复，并可通过后续扫描校正。
- [ ] 重复请求或重复点击不能误删其他文件，也不能将不存在文件无条件当成本次成功删除；重新扫描不能把已删除文件恢复为可用。
- [ ] 通过真实应用、真实临时存储及专门创建的测试文件验证确认、取消、单文件实际删除、关联文件保留、权限不足、缺失、路径越界、符号链接和目标变化；不模拟内部删除或数据库函数证明成功。
- [ ] 通过公开行为及真实存储故障场景验证删除与索引一致性；浏览器测试验证展示正确路径、风险文案和二次确认，所有测试和演示仅使用隔离临时媒体，绝不删除用户现有文件。
- [ ] 更新部署与使用说明，解释需要宿主机挂载和文件系统相应写权限、只读挂载下删除失败、系统没有恢复能力；交付本项所需数据状态、接口、界面与测试。
- [ ] 不提供批量、整季、整部电视剧、整目录删除或连带删除；若其他读取入口已存在，删除后它们也应明确返回文件不可用，不能要求尚未实现的播放器能力作为本项前置。
