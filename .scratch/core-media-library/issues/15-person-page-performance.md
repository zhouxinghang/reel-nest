# 人物关联作品页性能优化

Status: resolved
Blocked by: 14

## Scope

用户反馈人物全部作品页在媒体库较大时卡顿。保持人物来源隔离、有效资料过滤、电视剧/多版本去重及照片安全边界，消除每次请求扫描并解析全库演职员 JSON 的路径。

## Acceptance

- [x] 人物页按来源与人物 key 使用持久索引，只读取该人物关联作品的影片资料。
- [x] 人物照片关联不再重复执行完整作品页查询；旧缓存可自动、幂等地补建索引。
- [x] 资料新增、补齐、外部修改、过期、删除、换绑及旧 TMDB 表迁移不会留下错误人物关联。
- [x] 大型隔离媒体库性能回归、既有人物/资料测试、浏览器流程、race、vet 与构建通过。

## Comments

- 2026-10-01：领取；仅修改派生索引和人物读取路径，不操作用户媒体，不擅自重启现有服务。

## Answer

- 新增以资料缓存为真源的 `metadata_people` 派生索引及同步状态；旧库启动时一次性补建，后续资料写入在同一事务内更新，payload 外部变更由 SQLite trigger 使索引失效并在启动时重建。
- 人物作品接口从“读取全库 payload 并逐份解析演职员”改为先按 `source + person_key` 定位作品，只解析命中的少量标题；人物照片使用轻量身份查询，不再重复加载作品 payload。
- 隔离库 5000 部作品、目标人物 50 部关联的实际 HTTP 查询由约 2.69 秒降至约 6 毫秒；同库人物照片身份查询约 6 毫秒。全量 Go、人物增量 race、9 个资料 Chrome 流程、vet 和生产构建通过。
