# 03: 电视剧、季与单集组织

**What to build:** 家庭成员能区分电影与电视剧，在本地文件名识别结果的基础上按“电视剧 → 季 → 单集”找到具体视频；不能可靠识别的内容仍能从未匹配媒体进入文件详情。

**Blocked by:** 02（媒体目录扫描与基础媒体库浏览）

**Status:** resolved

**Parent:** [核心家庭媒体管理系统](/Users/bytedance/workspace/reel-nest/.scratch/core-media-library/spec.md)

**User stories:** 14, 16, 17, 18, 19, 20

## 范围与边界

只组织已有媒体文件，不等待 TMDB 资料，也不要求播放器已完成。领域命名遵循电影、电视剧、季、单集和媒体文件的区分。

## Acceptance criteria

- [x] 海报墙或等价浏览入口明确区分电影与电视剧；详情提供电视剧、季、单集的逐级导航，每个可观看条目可定位到具体媒体文件。
- [x] 能识别文件名中的常见季集标记，如 S01E01；季与单集按季号、集号合理排序，不仅按文件名字符串排序，并说明采用的识别规则。
- [x] 一个媒体文件只承载一部电影或一个单集，不将多集合一文件伪装成多个独立可操作文件。
- [x] 不同实际视频文件即使对应同一作品或季集编号也保留独立身份和可区分入口，不自动合并版本；不能只靠标题或季集编号唯一定位实际文件。
- [x] 无法可靠确定作品或季集编号的内容保留为未匹配媒体，仍可浏览并打开该媒体文件，不强行套用任意电视剧。
- [x] 组织结果在重复扫描及正常重启后保持一致；不改变原始文件名、不移动文件，也不依赖磁盘目录一定与作品层级相同。
- [x] 通过真实应用和隔离媒体目录验证电影/电视剧分类、跨季导航、季集数值排序、相同作品的不同文件版本及识别失败回退；浏览器测试覆盖从海报墙到具体单集详情。
- [x] 交付组织结果所需的持久化、接口、界面与测试；后续播放和删除通过稳定媒体文件身份接入，不在本项新增播放器或删除入口。

## Answer

2026-09-30：已交付本地电视剧、季与单集组织，完成上述验收。

- **持久化与接口**：增加 SQLite 组织迁移，从已有索引补充电视剧和单集关联，不访问源媒体、不改变已有媒体文件标识。后续扫描在同一事务中发布文件及组织结果。媒体库返回电视剧摘要，受保护的 `GET /api/series/{id}` 返回数值排序的季、单集和独立文件版本；单文件详情提供所属季集及未组织原因。
- **识别与身份**：仅处理电视剧目录，支持不区分大小写的 `S01E01` 等标记、前导零和第 0 季；优先文件名作品名，无作品名时保守使用接入目录内部的作品文件夹。文件名季号优先，不依赖目录层级。多集/范围、编号或作品名不明确时只保留一个未组织文件，不强制猜测。相同作品/季集的不同实际文件保留各自标识与路径；同名作品跨接入目录保持独立。规则和示例见 [README](/Users/bytedance/workspace/reel-nest/README.md)。
- **界面**：电影与电视剧分类、电视剧海报卡、季导航、单集数值排序、独立文件版本和返回所属季的入口。无法识别的文件仍可直接打开详情；本地组织不冒充 TMDB 匹配，未匹配分类仍保留全部未关联资料的媒体文件。
- **实际验证**：`go test ./...`（12 个应用级用例，03 新增 4 个并含 25 种命名子用例）、`go test -race ./...`、`go vet ./...`、前端构建、真实 Chrome 浏览器主流程、格式检查、Linux/amd64 交叉编译及依赖审计通过。浏览器覆盖海报墙 → 季 → 单集版本 → 具体文件详情 → 返回季，并检查桌面/窄屏布局。使用真实 02 旧版 HTTP 建库的独立升级脚本通过：源媒体离线时升级并再次重启，账号、3 个文件标识及 1 部电视剧/2 季/2 集均保留。详见 [验证记录](/Users/bytedance/workspace/reel-nest/docs/verification.md)。
