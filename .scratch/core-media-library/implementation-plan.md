# 核心家庭媒体管理系统：实现建议参考

本文件保留前期提出的技术栈、页面与工程默认值，作为实现建议而非已确认的技术约束。当前正式需求与 ready-for-agent 状态以 [需求规格](./spec.md) 为准；本参考文档不设置额外分诊或采访门槛，也不表示本轮已开始编码。

## 1. 推荐技术与部署

- Go 后端提供 API、媒体文件串流和前端静态资源；React + TypeScript 构建响应式网页，采用深色海报墙布局。
- SQLite 保存媒体索引、影片资料关联和家庭共用观看进度，不引入独立数据库、Redis 或任务队列服务。
- 一个应用容器，提供 Dockerfile、Docker Compose、配置示例和启动说明。SQLite、应用密钥及缓存使用独立持久化应用数据目录，不放进媒体目录；不把数据库放在 SMB/NFS 媒体共享上。
- 部署配置提供家庭共享账号密码、可选 TMDB 凭据、媒体根目录和观看设备能够访问的服务地址。配置示例不包含真实秘密，也不要求用户把密码或 API 凭据发到聊天中。
- 媒体通过既定的宿主机挂载目录接入。应用不管理 NAS 挂载，不安装或调用视频转码服务。

## 2. 最小页面集合

1. **登录**：家庭共享账号登录、退出；无注册、多用户或权限分级。
2. **媒体库**：海报墙、标题/文件名搜索、电影/电视剧分类、未匹配媒体入口、继续观看。
3. **详情**：海报、标题、年份、简介、文件信息；电视剧按季和单集展示；手动重新匹配、网页播放、外部播放器入口与单文件删除。
4. **网页播放器**：播放/暂停、拖动定位、续播、字幕选择/关闭、不兼容提示；可转向外部播放器。
5. **媒体目录管理**：添加目录并指定电影或电视剧类型、手动扫描、显示扫描状态及错误、显示 TMDB 配置状态。

以桌面浏览器为主要使用场景，布局兼顾窄屏浏览。不新增收藏、推荐算法、播放统计、自动连播、原生移动端或电视客户端。

## 3. 文件与内容组织默认值

- 电影支持“电影名 (年份)”文件名及独立电影子目录；电视剧以剧目录组织，单集从 `S01E01` 类编号识别，季目录可作为组织层但不代替单集编号。
- 起步识别的视频扩展名为 `mp4/m4v/mkv/mov/webm/avi/ts/m2ts/mpg/mpeg/wmv/flv`。收录不等于浏览器能够解码；不解析光盘镜像或播放列表。
- 一个视频文件对应一部电影或一个单集；同作品的不同版本不合并，分别保留。无法可靠识别时显示未匹配媒体，不直接把搜索第一项当成正确答案。
- 使用独立的媒体文件标识，不以标题或 TMDB ID 作为文件身份。同一文件重复扫描不重复收录，保留其匹配与观看进度；改名、移动或内容替换按新文件处理，首版不做文件迁移识别。
- 外挂字幕匹配同目录的 `<视频基本名>.srt/.vtt`，并支持 `<视频基本名>.<语言标记>.srt/.vtt`。只支持 UTF-8，非法编码或无法解析时明确提示，不改写源字幕。

## 4. 播放、授权与观看进度

- 原始媒体串流支持 HTTP GET、HEAD 和 Range 请求，使浏览器及外部播放器能够定位播放；不把整个大文件读入内存，也不转码视频。
- 网页及管理 API 需要共享账号登录。外部只读凭证仅对应一个媒体文件，不授予浏览、修改、字幕枚举或删除权限；服务端始终约束在已配置媒体目录内。
- 不实现串流链接自动过期。应用签名密钥持久化，普通重启不使有效链接无故失效；已删除或已被替换的媒体不得通过旧链接读取其他内容。
- IINA 使用官方打开 URL 的协议形式；PotPlayer 在兼容环境提供协议入口，始终提供复制串流地址。地址不能使用服务器自己的 localhost 或源文件路径。
- 浏览器每 10 秒及暂停、定位完成、播放结束时保存进度；异常关闭可能丢失最后一小段未保存进度。完成播放后从继续观看中移除，不按百分比推断看完；再次主动播放可从头开始。
- 进度按媒体文件保存，由家庭共享；多个浏览器观看同一文件时按最后收到的有效更新保存，不增加独立会话冲突合并。外部播放器不回传进度，也不自动携带外挂字幕。

## 5. 扫描、资料服务与异常默认值

- 添加目录后自动扫描一次，此后手动扫描；单目录避免重叠扫描，展示处理中、完成、失败状态。服务重启后未完成扫描显示中断，可手动重试，不引入定时扫描。
- 同一次完整扫描内先发现文件，再处理可选的影片资料请求，TMDB 不可用不阻断媒体收录或播放。
- 未配置 TMDB 或请求失败时保留文件名与占位图；手动重新匹配由用户选择候选，结果保存在应用数据中，不写 NFO 或重命名视频。
- 遵守 TMDB 的署名、限流和缓存期限要求；缓存不得被当作永久离线资料库，到期不能刷新时退回本地文件信息，而非阻断播放。
- NAS 挂载不可用、权限不足或扫描中断时报告错误，不批量清空媒体库。完整成功扫描后未见的文件标为不可用，保留原有记录与进度。

## 6. 删除安全默认值

- 只允许登录后选择一个已收录的普通视频文件；确认框显示路径和“永久删除，本系统无法恢复”。不提供按目录、按整季或多选批量删除。
- 拒绝越出媒体根目录、符号链接、目录和其他非普通文件操作；在执行时重新验证目标，不能只信任页面提交的路径。
- 文件未删除时不移除媒体记录；权限不足、文件变化或源目录不可用要明确报错，不误报成功。若文件删除成功但数据库更新失败，报告实际结果，后续扫描可校正不可用状态。
- 不连带删除字幕、图片或文件夹。不承诺立即中断已经建立的外部播放连接。
- 删除测试只使用专门创建的临时测试文件，不操作用户现有媒体。

## 7. 验收与交付

以下为前期验收建议清单。正式规格以运行中的应用对外边界作为一个主要测试切面，不要求为每个内部模块另建测试入口；冲突时以正式规格为准。

- 后端单元及集成测试：账号与串流权限隔离、错误凭证、Range/HEAD、重复扫描、扫描中断/根目录缺失、手动匹配、续播、字幕转换、路径越界、删除成功/失败及保留关联文件。
- 前端构建与核心交互检查：登录、搜索分类、电影与季集详情、未匹配降级、播放器与字幕、外部链接/复制、扫描反馈、删除确认与错误提示。
- 外部服务测试默认使用模拟响应；只有部署者自行配置凭据后才进行真实 TMDB 联通验证，不伪造联网成功。
- 提供可运行源码、测试、数据库初始化/迁移、Docker 配置、环境变量示例，以及启动、挂载权限、影片命名、备份和播放器使用说明。
- 外部播放器手工验收覆盖 macOS/IINA（1.4.4 或更新版）与 Windows/PotPlayer；无法实际验证的目标环境明确列为未验证，不把生成了链接当作播放已验收。

### 当前环境事实与验证限制

只读探查确认本机为 macOS/arm64，已有 Go 1.25.12、Node 26.7.0、npm 11.19.0、pnpm 11.25.0；当前 PATH 中未找到 Docker CLI。因此可安排本地 Go/前端开发与测试，但不能假设已有可用的镜像构建或容器运行环境。依赖版本在实现时按实际兼容性固定；容器运行和其他设备播放器验证须如实报告是否完成。

## 8. 实现顺序

1. 项目骨架、应用配置、SQLite、登录与文件访问边界。
2. 媒体目录与扫描、电影/电视剧组织、TMDB 匹配与降级。
3. HTTP 串流、浏览器进度、字幕、外部播放器入口。
4. 最小网页界面与安全的单文件删除。
5. 集成验证、Docker 交付配置、使用文档与未验证项清单。

后续执行以正式规格和已接受 ADR 为准；本次仅发布规格，不自动开始编码，也不将上述技术默认值记为已接受 ADR。
