# Reel Nest

面向局域网的家庭媒体库。一个家庭共享账号、一个 Go 应用、React/TypeScript 网页及本地 SQLite；不提供个人账号、注册或找回密码。

## 当前交付

- 家庭共享账号登录、受保护的媒体库、退出和会话失效。
- 账号以加盐密码哈希持久化；应用数据独立于媒体目录，正常重启无需重新配置账号。
- 允许根目录内的媒体目录接入、首次自动扫描/手动重扫、标题/文件名搜索、电影与电视剧分类、未匹配海报墙和文件详情。
- 本地电视剧 → 季 → 单集导航，按数值排序；同一单集的不同文件版本保持独立入口。
- 稳定媒体文件身份、完整扫描同步移除缺失记录、失败/中断扫描保留原有索引。
- 原始视频直放、HTTP GET/HEAD/Range、家庭共用续播与继续观看。
- Emby 风格全宽首页、横向媒体栏、家庭共享收藏与按实际入库时间排序的最近添加。
- 不过期的单文件只读串流、Pot/VLC/IINA 协议入口及复制地址兜底。
- 同目录 UTF-8 SRT/VTT 外挂字幕选择、切换与关闭；不改写源文件。
- TheMovieDB / TheTVDB 中文优先影片资料、自部署 MetaTube 电影资料、海报缓存与故障回退；按媒体目录启用和排序资料源，以及电影/电视剧手动修正匹配。
- 电影、电视剧详情展示演员、饰演角色和导演；支持长演员名单展开，旧资料缓存后台补齐。
- 单个源视频的路径核对、二次确认与永久删除；失败/索引异常明确反馈，不连带删除。
- 01–12 已完成；Docker 按要求跳过，其他实机限制见 `docs/verification.md`，任务状态见 `.scratch/core-media-library/map.md`。

## 本地启动（不需要 Docker）

需要 macOS 或 Linux、Go 1.25+、Node 22.13+（或兼容版本）与 npm。单机生产部署目标是 Linux Docker；不提供 Windows 服务端构建。

```bash
npm ci
npm run build
mkdir -p secrets
(umask 077; openssl rand -base64 24 > secrets/household_password.txt)
HOUSEHOLD_USERNAME=family HOUSEHOLD_PASSWORD_FILE="$PWD/secrets/household_password.txt" \
  DATA_DIR="$PWD/data" go run ./cmd/reelnest
```

在本机打开 `http://localhost:8090`，使用 `family` 和你本地密码文件中的密码。不要把真实密码提交到 Git、贴到聊天或通过命令行参数传入。示例目录、`.env` 和生成物均已忽略。生成密码命令只在首次配置时运行，不要覆盖已有密码文件。

再次启动可直接执行 `DATA_DIR="$PWD/data" go run ./cmd/reelnest`。已保存的账号优先于首次启动变量；修改环境变量或密码文件**不会**重置已存在的账号。请妥善保管密码；首版不提供自助找回。不要删除数据库来“重置密码”，这也会丢失后续媒体库数据。

应用默认监听 `:8090`。局域网其他设备访问 `http://<宿主机局域网IP>:8090`，不是观看设备上的 `localhost`。防火墙只开放可信家庭网段，不要做公网端口转发。HTTP 不加密传输，只适用于可信局域网；需要传输保护时部署同源 HTTPS 反向代理，并设 `COOKIE_SECURE=true`。

开发可运行 `npm run dev`，Vite 将 `/api` 和 `/stream` 代理到本地 8090；正式运行始终使用构建后嵌入 Go 程序的页面。

## 单机 Docker 部署

**已提供配置，但本机无 Docker；按用户要求跳过镜像构建、容器运行、容器持久化和容器局域网实测。以下是待具备 Docker 环境验证的部署步骤。**

```bash
cp .env.example .env
mkdir -p secrets
(umask 077; openssl rand -base64 24 > secrets/household_password.txt)
# 本地 Compose 文件型 secret 必须允许容器 UID 10001 读取。
# secrets 目录在宿主机保持仅自己可访问；文件只包含此应用密码。
chmod 700 secrets
chmod 444 secrets/household_password.txt
docker compose up --build -d
```

在 `http://<宿主机局域网IP>:8090` 登录。容器以非 root 的 UID/GID `10001:10001` 运行，应用数据存于 Docker 命名卷 `app_data`，在容器内为 `/data`，不在镜像层或媒体目录中。**不要运行 `docker compose down -v`，它会删除应用数据。** 正常 `docker compose restart` 或重新创建容器不删除命名卷。默认绑定所有宿主机接口；可在 `.env` 把 `HOST_BIND` 改为指定局域网地址或 `127.0.0.1`。

媒体通过宿主机预先挂载的目录接入：例如宿主机 `/mnt/nas/movies` 挂到容器 `/media/movies`。网页只能使用容器可见的 `/media/movies`，不能填写宿主机路径。宿主机负责 NAS 的 SMB/NFS 挂载和在线状态；应用不管理网络共享，不上传、下载、重命名或移动视频。应用使用部署者配置的 `MEDIA_ROOTS` 限定可接入范围；空库启动仍不需要媒体、NAS 或 TMDB。

读取视频需要进程用户对目录有遍历/读取权限、对文件有读取权限。删除还需要相应父目录写入/执行权限、文件系统/ACL 授权及可写挂载；默认仍只读挂载。不建议对共享目录使用 `chmod -R 777`。

## 接入媒体目录

### 本地进程

由部署者配置允许范围（多个路径用系统路径分隔符 `:` 分隔）。根目录必须与应用数据目录分离，不允许根目录包含应用数据库，也不允许将媒体根目录放到应用数据目录下。

```bash
MEDIA_ROOTS="/absolute/path/to/movies:/absolute/path/to/series" \
  DATA_DIR="$PWD/data" go run ./cmd/reelnest
```

登录后进入“媒体目录”，填写**媒体库名称**和其中一个根目录或其子目录的**绝对路径**，选择电影或电视剧，点击“添加并扫描”。一个接入目录对应一个独立媒体库；名称去除首尾空白后为 1–80 个字符，不含控制字符，可在管理页“修改名称”，不会改名或移动磁盘目录。已有目录升级时自动使用文件夹名补全名称，不重新扫描，不改变媒体身份、匹配、收藏和观看进度。电影按单个文件展示；电视剧尝试根据本地文件名建立季/单集导航。页面显示扫描中、完成、失败/中断；同一目录不能重叠扫描，重复或相互包含的目录不能重复接入。

### Docker 挂载（待容器实测）

在 `.env` 设置已存在的宿主机目录 `MEDIA_HOST_PATH=/mnt/nas/media`，然后：

```bash
docker compose -f compose.yaml -f compose.media.yaml up --build -d
```

在页面输入 `/media` 或其子目录，例如 `/media/movies`。宿主机目录必须已存在；配置拒绝自动创建空宿主机挂载目录。默认挂载为**只读**，足够用于扫描、浏览、播放和字幕；删除会明确失败，不会绕过只读限制。需要删除时使用下述显式可写配置。容器用户 UID/GID `10001:10001` 必须能遍历子目录并读取视频。

### 扫描和身份规则

- 支持 `mp4 / m4v / mkv / mov / webm / avi / ts / m2ts / mpg / mpeg / wmv / flv`，不区分扩展名大小写。只收录普通文件，忽略字幕/图片等非视频及所有符号链接，不进入符号链接目录。格式收录不等于浏览器可解码。
- 一个实际文件有独立随机标识；按目录、相对路径、设备/inode、大小和纳秒修改时间识别版本，不以标题或TMDB ID 作身份。普通重扫/应用重启保留仍存在文件的标识；改名、移动或常规内容替换视为新版本，成功重扫会移除已不存在的旧记录。不会进行视频全量内容哈希，刻意同时保留 inode、大小和修改时间的原地篡改不在当前识别能力内。
- 整个目录成功扫描后才原子发布索引。子目录不可读、文件在扫描时变化、根目录缺失/被替换或应用中断时，保留上一次完整索引，不把部分结果当成删除。强制终止后的未完成扫描在下次启动标为“扫描已中断”，可手动重试。
- 已接入根目录会记录文件系统身份，以免 NAS 离线后同路径下的空挂载点被误认为成功的空扫描；需要恢复原媒体目录后重试，不会把同路径的新目录自动当作原目录。
- 完整成功扫描会从媒体库删除未找到的文件记录，并清理对应的观看进度、文件级资料关联和已经没有单集的电视剧；失败或中断扫描仍完整保留上一次索引。没有定时扫描或文件监听，源目录变化后需要手动重新扫描。
- 没有在线资料源凭据也能扫描、浏览和播放；无有效资料时以原文件名和本地占位海报显示。只有配置可选凭据并在目录启用后才请求对应资料源，任何匹配操作都不修改源文件。

## 首页、收藏与最近添加

- 首页采用顶部「首页 / 收藏 / 最近添加」标签和横向媒体栏，「我的媒体」按已接入目录展示具名卡片（包括空库），点击进入只浏览该目录的内容；继续观看和最近添加跨媒体库汇总，最近添加统一展示最新 20 项，点击栏目标题查看完整列表；左侧导航收起为菜单，搜索和目录管理位于右上角。保留 Reel Nest 品牌，不冒用 Emby 品牌或展示未实现的功能。
- 点击海报或详情页上的爱心添加/取消收藏；电影、单集文件和整部电视剧分别收藏，互不连带。收藏存入应用 SQLite，由家庭共享账号的所有设备共用，刷新/重新登录/正常重启后保留，不依赖浏览器本地缓存，也不改写观看进度或源文件。失败时保持原状态并可重试。
- 全局分类、搜索和收藏按媒体库分组，显示名称与来源路径；同名媒体库、同名文件不合并。可用“选择媒体库”切换范围，单库入口支持刷新和浏览器前进后退。分组内按所选规则排序，分组顺序由各组排序后的首项决定。
- 「收藏」可按电影/电视剧筛选，按最近收藏或标题排序。「最近添加」不按目录分组，电影和电视剧统一按文件首次被完整成功扫描收录的时间排序，不按磁盘修改时间；同批次按稳定标识排序，普通重扫不会置顶旧文件。电视剧以当前单集中最新收录时间排序，新单集入库会将整部电视剧提前。
- **升级前的历史文件没有收录时间记录**：显示「收录时间未知（旧版数据）」，排在有记录的新文件之后，不伪造历史日期。升级、重扫或获取影片资料都不会补造该时间。新文件版本遵循既有身份规则，作为新收录项。
- 完整成功扫描移除缺失记录时，同时清理对应文件和空电视剧的收藏；暂时扫描失败仍保留。取消收藏不删除源文件，串流凭证不能授权收藏操作。

## 安全地永久删除单个源文件

从**电影或具体单集的文件详情**点击「删除源文件」。首次点击只核对文件并显示应用可见的完整目标路径（容器中是挂载后的路径），不会删除。核对路径和「本系统无法恢复」提示后，独立点击「确认永久删除」才提交；「取消」或 Escape 关闭不删除。确认有效期 10 分钟，过期须重新打开核对。删除已提交时不能撤销或关闭成“已取消”，请等待结果。

- 实际删除选中的**一个普通视频文件**，不是仅隐藏媒体记录。字幕、海报、其他文件版本、其他单集和目录全部保留；没有整季、整部电视剧、目录或批量删除，没有回收站/恢复功能。硬链接的其他目录项也不会连带删除，因此不能保证立即释放所有占用空间。
- 仅家庭共享账号会话可提交，串流链接、公开文件 ID、确认字符串本身都不能替代登录。两步请求不接受客户端路径或路径数组，服务端始终从受管理文件标识取得路径。
- 预览和执行都复用媒体根范围、根身份、逐层真实目录、非符号链接、普通视频及已扫描版本核验；确认还绑定完整路径、父目录设备/inode、文件设备/inode/模式/大小/纳秒 mtime/ctime。执行前重新遍历和核对；发现目标替换、移动、原地修改、挂载变化即拒绝，不沿旧确认删除另一版本。
- 权限错误、只读文件系统或缺失会明确报告；没有真正删除时不清除索引或伪报成功。失败后确认按钮禁用，需要关闭后重新核对。网络断开导致结果不明时，先重新扫描核实，不能把无响应当作没删除并自动重试。
- 删除成功后先保留文件记录并标为**不可用**，不再出现在继续观看中；网页当前播放卸载，后续网页读取、字幕和旧串流链接返回不可用。下一次完整成功扫描会移除该记录及对应进度/文件级资料关联；已经打开的其他播放连接可能继续读取原句柄，不能承诺立即终止或立即释放空间。
- 文件系统删除和 SQLite 更新不是一个原子事务。如果文件已删除但索引写入失败，页面明确提示「源文件已永久删除，但索引未更新」，绝不表示可恢复。当前详情停止播放；持久化索引可能仍显示上次扫描状态，修复应用数据存储并重新扫描后会校正。若进程在两步之间被强制终止，也须这样核实并校正。
- 同一应用进程的扫描与删除串行化，避免扫描的旧快照重新发布可用状态；重复删除会报不可用，不能把“早已不存在”当作本次成功。不要同时运行多个应用实例写同一媒体目录。

### 显式启用写权限（Docker 仍未实测）

默认 `compose.media.yaml` 保持只读。确需删除时，**改用** `compose.media-write.yaml`（不要同时叠加两个媒体配置）：

```bash
docker compose -f compose.yaml -f compose.media-write.yaml up --build -d
```

宿主机 NAS 必须已经挂载且可写；`MEDIA_HOST_PATH` 指定既存媒体目录。容器 UID/GID `10001:10001` 需要视频读取权限、各层目录遍历权限、目标父目录写入和执行权限，还需满足 NAS 导出策略、ACL、sticky bit/保护标志。修改 bind mount 为可写**不会**自动授予这些权限；不要用 root 或递归 `chmod 777` 绕过授权。只授予确需删除的目录权限；建议先用专门创建的临时媒体验证。

**宿主机并发边界：**删除采用已核对的父目录句柄与 `unlinkat(..., 0)`，不递归、不能删除目录、不跟随末端符号链接。POSIX 不提供“仅当 inode 仍匹配才 unlink”的原子系统调用，最终核对与 unlink 之间仍存在极短的外部写入竞态；应用锁只能约束本进程。部署时不要让下载器、整理脚本、其他进程或不受信任的本地/NAS 写入者在删除时并发替换文件/父目录或切换挂载。本实现不宣称能防御恶意宿主机写入竞态，也不是全文件内容认证；不满足此边界时请保持只读挂载。

## 电视剧、季与单集

在海报墙的“全部”或“电视剧”分类中，已识别内容按电视剧展示；打开后选择季，再选择具体单集的文件版本。季号/集号按数值排序，不按字符串排序。文件详情提供返回所属电视剧及对应季的入口。

### 本地识别规则

- 只处理标为“电视剧”的媒体目录；电影文件即使包含 `S01E01` 也不会变成单集。支持不区分大小写的 `S01E01`、`S1E2` 等标记，前导零不影响季/集号；也支持有可靠作品目录的纯数字文件名，例如 `太平年/01.mp4` 识别为第 1 季第 1 集。支持季号 0–999、集号 1–9999，第 0 季显示为特别篇。
- 优先使用标记前的文件名作为电视剧名，将点号/下划线转换为空格、折叠空白并修剪边缘空格和连字符。保留年份等区别信息，不按 TMDB 标题推断。英文名与季集标记之间需要分隔符；中文名可直接接季集标记。
- 若文件名只有季集标记，则使用已接入目录**内部**的最近父目录名；父目录为 `Season 1`、`S01` 或 `第1季` 时，上移一级取作品目录名。不会把接入根目录本身当作作品名；`TV / Series / media / downloads / 电视剧` 等通用父目录也不会被当作作品名。
- 文件名包含 `S01E01` 时，季号/集号以文件名为准，例如 `城南往事/Season 02/S01E05.mp4` 仍属于第 1 季第 5 集。纯数字文件名默认属于第 1 季；若直接位于 `Season 2`、`S02` 或 `第2季` 目录，则从该目录取得季号，并从上一级目录取得电视剧名。
- 多个季集标记、`S01E01E02`、`S01E01-E02`、`S01E01-02`、`S01E01+E02` 等多集/范围形式，以及无法可靠确定作品名或编号的内容，保留为一个未组织的媒体文件；在详情显示原因，不虚构多个可操作的单集。未支持的命名格式不会被强行整理。
- 在**同一个已接入媒体目录**内，按规范化且不区分大小写的本地作品名分组。同名作品在不同接入目录内保持独立，海报卡和详情显示来源目录。此为本地组织规则，不是对作品真实身份的外部认证；请在命名中保留年份等必要区分。
- 同一作品、季、集可以对应多个独立媒体文件。每个文件的路径、标识、大小及可用性分别保留，播放及删除仍只能使用具体媒体文件标识，不以季集号代替。

示例（目录标为电视剧）：

| 文件相对路径 | 组织结果 |
| --- | --- |
| `flat/星河.S2E10.1080p.mkv` | 星河 → 第 2 季 → 第 10 集 |
| `星河/Season 01/S01E02.mp4` | 星河 → 第 1 季 → 第 2 集 |

### 从 02 升级

停止旧应用并备份整个应用数据目录，然后用新程序和原 `DATA_DIR` 启动。新版本自动在事务中迁移并从**已有索引**补充本地季集组织，不重建媒体文件标识、不访问源媒体、不要求重新扫描；离线媒体也能完成迁移。原账号继续有效。重复启动不会重复迁移；新增和后续扫描与文件索引在同一个事务中更新组织结果。

## 网页播放与家庭共用观看进度

从电影或具体单集文件详情点击「网页播放」，自动尝试从家庭共用进度播放并进入网页全屏（铺满网页，不强制进入操作系统全屏）；「从头开始」则从零播放。按 Esc 或右上角关闭播放器会暂停并保存进度，返回详情。若浏览器拦截自动播放，会提示点击「开始播放」。浏览器直接接收原始视频；可用原生控件或「播放位置」拖动定位。未匹配媒体也能播放，不依赖 TMDB。服务不安装/调用视频转码程序、不将整部视频载入内存；支持 GET、HEAD、单段/多段 Range、If-Range。

- 浏览器支持取决于容器、视频/音频编码和设备。当前实测样本是 **60 秒、640×360、12 fps、无音轨 VP8/WebM**，测试浏览器为本机 Chrome；这不是 H.264、HEVC、MKV 或音轨的兼容性保证。
- 解码失败会提示使用外部播放器；文件缺失、挂载/权限错误和文件被替换单独反馈，不统一称作格式不兼容。恢复媒体后重新扫描并打开正确文件版本。
- 网页每 10 秒及暂停、定位完成、播放结束时保存进度，并在页面隐藏/离开时尽力补存。异常关闭可能丢失最后一小段进度；保存失败会提示。
- 进度按稳定媒体文件身份保存，同一家庭账号的所有浏览器共享；同作品的不同文件版本不串用。多个浏览器按服务端最后收到的有效更新保存，不合并播放会话。
- 有未完成进度的可用文件显示在「继续观看」，详情重新打开自动定位。只有实际播放结束事件标记看完，不按百分比推断；看完从继续观看移除，下次主动播放从头开始。重扫、正常重启不清进度。

## 外部播放器串流

详情页提供 Emby 风格的 Pot、VLC、IINA 和「复制链接」按钮。串流地址在后台准备好后，点击对应播放器即可请求唤起应用，无需先点「获取串流地址」；也可以直接复制，在播放器的「打开 URL」中粘贴。网页播放失败时先关闭播放器返回详情。没有安装/没有协议注册/浏览器拒绝唤起时，仍可手动选中完整地址复制；网页不能确认外部应用是否已经开始播放。

- **必须用观看设备可以访问的服务器局域网 IP 或域名打开网页。** 串流地址使用该网页的 origin，不采用服务进程自己的 localhost、容器地址、磁盘路径或客户端伪造的转发头。`localhost`/`127.0.0.1` 页面生成的地址只供本机使用，页面会提醒。应用部署在同源根路径；反向代理必须转发 `/stream/` 且保留 Range/HEAD，不缓存鉴权结果、不记录完整查询参数。
- IINA 基线是 **1.4.4+**，使用 `iina://open?url=<完整编码的HTTP地址>`。不要使用存在 URL 处理漏洞的旧版。[官方安全公告](https://github.com/iina/iina/security/advisories/GHSA-w5xh-98j7-jp5q)。
- VLC 提供 `vlc://<HTTP地址>`；是否可唤起取决于设备上的协议注册，不保证所有平台/安装方式都支持。未唤起时使用「复制链接」在 VLC 中打开网络串流。
- PotPlayer 提供 `potplayer://<HTTP地址>`；并非所有 Windows 版本/安装方式都会注册该协议，不保证免配置一键打开。优先尝试复制地址兜底，不要求修改系统注册表。
- 链接使用持久化 256 位安全随机密钥的 HMAC-SHA256，只授予**一个媒体文件**的读取权。无浏览器 Cookie 的客户端可 GET/HEAD/Range；它不能浏览媒体库、扫描、读取字幕、写观看进度或执行管理操作。
- **链接不会随时间自动失效，网页退出也不撤销它。持有链接者能读取该视频；不要贴到公开聊天、日志或公网。** 不提供公开分享、自动续签或链接生命周期管理。仅适用于可信家庭局域网，HTTP 本身不加密；有传输保护需要时配置同源 HTTPS。
- 普通重启保留签名密钥和链接；备份应包含整个应用数据目录。源文件缺失/替换或目录挂载改变会拒绝读取，旧地址不能访问同一路径下的新版本。文件身份检测采用现有元数据指纹，不声称进行全视频内容哈希校验。
- 获取链接、点击协议和串流读取都**不写网页观看进度**。外部播放器自行加载字幕，不回传进度；没有声称实际 IINA 或 Windows/PotPlayer 兼容性已经验证。

## 网页外挂字幕

播放器「外挂字幕」中选择字幕；选择「关闭字幕」停止显示。无需重新扫描，重新打开播放器即会检查与原视频同目录的候选。服务只读取字幕，不改写视频/字幕，也不进行视频转码。

匹配示例（视频 `归途.webm`）：`归途.srt`、`归途.vtt`、`归途.zh.srt`、`归途.zh-Hans.vtt`、`归途.en.vtt`。视频基本名大小写精确匹配；字幕扩展名不区分大小写。可选语言标记仅支持英文字母、数字、`-`、`_`；不匹配其他基本名或多段后缀（如 `.zh.forced.srt`），忽略所有符号链接。列表以完整文件名和格式区分版本。

- 仅支持 **UTF-8**（可带 BOM）；支持 LF、CRLF、CR 换行。每份字幕上限 **2 MiB**；过大、非 UTF-8、时间/结构错误均明确报错，视频仍可播放。
- SRT 的 `HH:MM:SS,mmm` 会转换为真正的 WebVTT 时间轴和文件头，不是只改扩展名。VTT 支持文件头、可选 cue 标识、NOTE 注释、常见 cue 位置设置和文本标记；字幕按开始时间非递减排列、结束晚于开始，允许重叠 cue。
- 首版不支持 VTT `STYLE`/`REGION` 块、内嵌字幕提取、ASS/SSA 特效或字幕烧录；遇到不支持的块/位置设置不会误报加载成功。浏览器原生渲染文本字幕，不把字幕文本插入页面 HTML。
- 字幕列表和读取都要求家庭共享账号；串流凭证不能访问。候选标识绑定媒体文件、字幕名及文件指纹，修改/替换字幕后需重新打开播放器获取新候选。

### 从 03 升级到播放版本

停止旧应用、备份整个 `DATA_DIR`，使用原目录启动新版。新增进度表和串流密钥自动初始化，不重建媒体文件、账号或季集关系；不会为尚未播放的文件伪造进度。无需重新扫描。正常重启保留已保存进度和外部串流链接；不要删除数据库或单独替换密钥表。

## 影片资料源与故障降级（07、12）

### 按媒体目录设置优先级

进入「媒体目录」，新增时或在已接入目录下勾选 **TheMovieDB (TMDB)** / **TheTVDB (TVDB)** / **MetaTube（仅电影）**，用 ↑ / ↓ 排序，编辑已有目录后点击「保存资料源」。每个媒体目录及其递归扫描的子文件夹使用同一配置，互不影响。新目录和旧库升级默认 **TMDB → TVDB**，MetaTube 需显式勾选，不自动加入已有目录；全部取消可暂停该目录的自动获取。这里下载的是**影片资料和海报，不是视频文件**。

- 从高到低依次尝试；未配置、超时、限流、服务失败或没有唯一可靠候选时尝试下一源，首个可用作品资料成功后停止。只有唯一精确标题或 MetaTube 影片编号（含可用年份）才自动关联；多候选不会随意选中。
- 每次请求受独立来源的超时/限流约束；一个来源故障不阻断另一个来源，也不阻断扫描、本地浏览或播放。海报或简介缺失可保留已有标题并显示占位/提示，不跨来源混合不同作品字段。
- 修改顺序会立即排队重新评估该目录的**自动**匹配，已确认的手动作品不会被覆盖。资料获取期间保存可能返回忙，请稍后重试。配置与来源身份持久化，重扫/重启保留。
- 顺序未改变且缓存有效时继续使用缓存（含先前回退结果），不会每次扫描都重复下载。有效缓存按来源、类型和 ID 隔离；未获取新资料成功前保留原有效关联。禁用来源/全部取消不会删除既有资料，到期后不再自动获取禁用来源的资料。

### TMDB 凭据

使用部署者自己的 **API Read Access Token**（Bearer token），不是 v3 短 API Key。到 [TMDB 账号 API 设置](https://www.themoviedb.org/settings/api) 申请并接受其使用条款；不要把真实凭据贴到聊天、提交仓库或放在浏览器代码中。应用不需要 TMDB 用户登录会话。

- **本机**：把 token 保存到仅部署者可读的 `secrets/tmdb_read_access_token.txt`，启动时设置 `TMDB_READ_ACCESS_TOKEN_FILE="$PWD/secrets/tmdb_read_access_token.txt"`。也支持 `TMDB_READ_ACCESS_TOKEN` 环境变量；文件优先；文件缺失/不可读时记录不含秘密的警告并禁用该来源，不阻止本地应用启动。改动后重启，设置不会改变家庭共享账号。
- **Docker（本轮未验证）**：同目录创建该 secret 文件，按家庭账号 secret 的方式授予容器 UID 10001 读取权限；执行 `docker compose -f compose.yaml -f compose.tmdb.yaml up --build -d`。媒体挂载同时追加 `-f compose.media.yaml`。不需要资料服务时省略 TMDB override，不必创建空 secret。
- TMDB 凭据仅保留在后端进程并通过 HTTPS Authorization 头发送给 TMDB API，不写入数据库、不回显到网页或日志、不发送给图片 CDN。部署者应保护进程环境和 secret 文件。测试专用服务地址仅能通过 Go `app.Config` 注入，生产启动器不暴露此配置。

### MetaTube 服务地址与 Token

接入用户提供接口文档中的自部署服务，仅获取**电影资料和图片**，不下载视频。服务地址在启动时读取，网页仅负责按目录启用和排序，不保存或展示 Token。

- **本机**：设置 `METATUBE_URL` 为服务根地址，例如 `http://192.168.1.20:8080`；反向代理路径和末尾 `/v1` 也支持。把 Token 保存到仅部署者可读的文件，设置 `METATUBE_TOKEN_FILE="$PWD/secrets/metatube_token.txt"`，或直接设置 `METATUBE_TOKEN`。文件优先并去首尾空白；文件不可读时不回退环境变量，会以无 Token 请求（有鉴权的服务将返回 401），本地播放不受影响。
- **Docker**：设置私有 `.env` 的 `METATUBE_URL`，创建 `secrets/metatube_token.txt` 并授予容器 UID 10001 读取权限，执行 `docker compose -f compose.yaml -f compose.metatube.yaml up --build -d`。可叠加媒体挂载与其他资料源 override。它只连接已有服务，不负责部署 MetaTube；地址必须可从 Reel Nest 容器访问，`localhost` 指容器自身。服务未开启鉴权时可使用空 Token 文件。
- 改配置后重启 Reel Nest，并在「媒体目录」勾选 **MetaTube（仅电影）**、调整顺序后保存。未设置地址时来源禁用；配置成功的状态不代表已验证服务连通。支持可信局域网 HTTP，但 HTTP Token 未加密，跨不可信网络请使用 HTTPS。地址不接受 URL 内用户名密码、查询参数或片段。
- 按文档调用 `GET /v1/movies/search?q=...&fallback=true` 和 `GET /v1/movies/{provider}/{id}?lazy=true`；Token 仅通过后端 `Authorization: Bearer ...` 发送。标题、编号或影片主页 URL 都可用于手动搜索，由 MetaTube 汇总自身已启用的 Provider。HTTP 404 视为空结果，最多展示 20 个去重候选；不完整/歧义结果不自动匹配。
- Provider 名大小写不敏感，ID 保留原始字符串；持久保存 `(provider,id)` 到站内数字 `sourceId` 的映射，跨 Provider 同 ID 不冲突，重启和资料过期不丢关联。映射不是 MetaTube 原始 ID，也不复用 TMDB/TVDB ID。换服务地址应指向相同身份语义的 MetaTube 实例。
- 三类图片只通过该服务的 `/v1/images/primary|thumb|backdrop/{provider}/{id}` 获取，不抓取响应内任意图片 URL、不跟随重定向、不向公开图片接口发送 Token；保留同源认证、5 MiB 限制、类型校验和持久缓存。背景图按 MetaTube 接口语义可能仍带文字，不承诺无字。
- 从完整影片详情映射简介、发行年份和 `actors` / `director` 姓名，不额外猜测人物 ID、角色或照片。人物页仅列出该作品范围的本地关联；文档没有电视剧季集接口，因此不会把电影结果用于电视剧，后续可用来源继续回退。翻译、评论和演员独立搜索不属于本次接入。
- 服务端可自行配置 Provider 优先级；Reel Nest 不修改 MetaTube 的运行参数。Token 不入数据库、不返回前端或错误正文。每个来源最多 20 秒、总匹配预算 65 秒；来源间独立冷却，图片失败不丢弃已获取的影片资料。

### TVDB 凭据

从 [TheTVDB API 信息](https://thetvdb.com/api-information) / 账号后台取得自己的 **v4 API key**。使用 user-supported key 时还须有效订阅对应的 PIN；其他类型的 key 不传 PIN。使用范围受所持许可和 TheTVDB 条款约束，本仓库不提供他人凭据或额外数据授权。

- 本机：保存到仅部署者可读的文件，启动时设置 `TVDB_API_KEY_FILE="$PWD/secrets/tvdb_api_key.txt"`；如需 PIN，再设置 `TVDB_PIN_FILE="$PWD/secrets/tvdb_pin.txt"`。也支持 `TVDB_API_KEY` / `TVDB_PIN`，文件优先，变更后重启。
- Docker（未实测）：准备 `secrets/tvdb_api_key.txt` 并授予容器 UID 10001 读取权限；启动命令追加 `-f compose.tvdb.yaml`，可与 `-f compose.tmdb.yaml` 同时使用。需要 PIN 时设置私有 `.env` 中的 `TVDB_PIN`，或自行添加 secret 挂载并设置 `TVDB_PIN_FILE`；不需要 PIN 时留空，不创建不必要的凭据文件。
- 后端通过 HTTPS `POST /login` 发送 key / 可选 PIN，缓存 Bearer token 后请求 v4 的电影/电视剧搜索与详情。凭据和 token 不入数据库、不返回浏览器、不发送至海报域名。中文 `zho` 优先，缺少时回退 `eng` 或原文。海报仅从受信任的 TheTVDB artwork 域名获取，不代理任意外部 URL。
- 状态栏分别展示各资料源是否已配置、是否冷却。“已配置”仅表示本地存在凭据（MetaTube 为服务地址），不代表许可、订阅或真实网络已经验证。
- 实现依据：[官方 v4 API / OpenAPI](https://github.com/thetvdb/v4-api)、[v4 API 文档](https://thetvdb.github.io/v4-api/)。官方登录 token 有效期为一个月，应用保守按一天重新登录；失效后不在同次操作内无限重试。

### 自动获取、缓存与署名

**获取和显示：** 成功扫描发布本地文件后，独立后台工作器尝试匹配电影、已组织的电视剧；启动时也检查已有索引，不重新扫描媒体目录。网页显示配置/处理/失败状态，按钮“匹配 / 刷新到期资料”可重试未匹配项与到期缓存，以及补齐缺失/已到重试时间的演职员资料；有效标题、海报不重复抓取。不运行定时媒体扫描。未组织的电视剧文件保留原样，不强行推测所属作品。

电影查询使用去除扩展名的本地文件名，支持末尾 `(年份)`，例如 `Arrival (2016).webm`；电视剧使用已识别的本地作品名。仅在单页完整候选中，规范化标题或原始标题精确相同、可用年份相符且结果唯一时自动关联；不取任意首项。分辨率/发行组等额外文件名标记不做冒进清洗，可能需要手动匹配。不同文件版本仍使用各自标识，电视剧资料不会重写本地季集层级。

TMDB 查询及详情优先 `zh-CN`，缺少可用字段时尝试 `en-US`；TVDB 使用 `zho` / `eng` 翻译，再回退到原始标题/本地文件名/占位图。海报墙、详情和标题搜索使用有效资料；文件详情始终保留原始文件名、路径和媒体标识。海报通过受家庭账号保护的本地接口读取缓存，不从浏览器携带 token 访问外部服务。没有或失效的资料均不阻止本地播放、进度保存、字幕及独立串流。

**请求失败边界：** TMDB/TVDB 单次请求默认最长 5 秒，MetaTube 默认 15 秒；每个来源至多 20 秒、整个目标至多 65 秒。每个来源的资料请求同一时刻最多一个，两次请求起点至少间隔 250 毫秒；人物照片与影片横图使用独立节流队列。JSON 上限 1 MiB，单张海报上限 5 MiB，只接受 JPG/PNG/WebP 响应及受信任图片域名/路径，不跟随重定向。没有自动重试循环。401/403/5xx 和 429 会进入至少一分钟冷却；429 按 `Retry-After` 延长冷却，反馈原因后由用户重试。中文回退或海报失败保留其他有效资料；配置错误、网络超时或服务失败不会回传外部原始响应/凭据。

**缓存与离线边界：** 资料及海报缓存有效期 **30 天**（小于六个月），成功获取后保存在本机应用数据 SQLite 中。每次读取都排除到期条目，启动及每小时清理过期资料/海报；停机期间不展示缓存，下一次启动先清理。刷新失败不继续展示到期的在线资料内容，但保留媒体文件、观看进度和用户选择的关联 ID。缓存不构成永久离线资料库。备份同样可能包含当时缓存，应按相同期限轮换/清理旧备份。

**署名与条款：** 页面“关于与资料署名”使用 TMDB 官方标志并展示：

> This product uses the TMDB API but is not endorsed or certified by TMDB.

非商业使用及署名要求见 [TMDB FAQ](https://developer.themoviedb.org/docs/faq)、[品牌指引](https://www.themoviedb.org/about/logos-attribution)、[API 条款](https://www.themoviedb.org/api-terms-of-use) 和 [限流说明](https://developer.themoviedb.org/docs/rate-limiting)。本仓库不授予 TMDB 数据/图像的额外许可，商业使用需另行授权。官方标志原始来源：`https://files.readme.io/29c6fee-blue_short.svg`（官方文档所用标志），未改变比例或颜色。

页面同时展示指向 TheTVDB 的资料署名链接；详情标明实际采用的来源。

当前自动化使用独立可控 TMDB / TVDB 服务；**本次未使用真实凭据，真实 API 联通、许可有效性及中文覆盖未验证**。抓取官方公开文档不等同于真实资料请求通过。


### 影片图片：Primary / Thumb / Backdrop

按 Emby 的图片用途分开选择与展示，不再将一张竖版海报裁切用于所有位置：

| 图片 | 用途 | 缺图回退 |
| --- | --- | --- |
| Primary（竖版海报，`posterUrl`） | 海报墙、收藏、人物作品卡、详情左侧 | 本地标题占位 |
| Thumb（横版封面，`thumbUrl`） | 首页媒体入口、16:9 继续观看卡片 | Backdrop → 完整海报（留边、不拉伸）→ 占位 |
| Backdrop（详情背景，`backdropUrl`） | 电影、电视剧、单集详情的背景层 | Thumb → 纯色；不把竖版海报充当背景 |

- TMDB 没有单独的 Thumb 分类：从 `/images` 的横向 backdrops 中优先选中文、再英文带语言图片作为封面，详情背景优先无语言图片；同级按评分和尺寸选择。上游只提供一张横图时，两种用途可共用该图，仍与竖版海报分离。默认封面使用 w780、背景使用 w1280。
- TVDB 从 `/artwork/types` 识别电影/电视剧背景类，再从完整 extended 的 artwork 依据类别、横向比例、`includesText`、语言及评分选择；排除横幅、标志和竖图。不混用不同来源或作品的图片。
- 单集沿用所属电视剧图片，不冒充单集剧照；未匹配媒体仍有占位。没有新增图片上传、本地 sidecar 图片导入、背景轮播或对源文件的写入。
- 横图按需从后端受控下载，网页只请求同源认证接口。图片不向 CDN 发送凭据、不跟随重定向，单张最多 5 MiB，仅允许签名与 Content-Type 一致的 JPEG/PNG/WebP。图片缓存与元数据写入、人物照片队列分离；并发请求合并，失败保存 24 小时重试间隔，正常缓存不超过所属资料的原 30 天期限。
- 旧有效资料无需清空：重建、重启后后台补齐，或点击“匹配 / 刷新到期资料”。仅补充图片字段，不改变标题、原海报、手动关联、进度、收藏或原缓存期限。补齐失败保留基本资料；没有图片的成功结果不会每次扫描重试。

### 演员与导演（13）

- 电影、电视剧及单集详情的「演职员」展示演员姓名、饰演角色和导演；演员默认显示前 8 位，可展开其余名单。未知角色标注“角色未提供”，演员/导演缺失与请求失败分别提示。单集使用整部电视剧资料，**不代表本集专属演职员**。
- 沿用当前匹配作品的来源和 ID，不从另一源拼接演职员。TMDB 电影使用 `credits`，电视剧使用 `aggregate_credits` 汇总角色/导演；只接受 `Director` 职务，不把创作者、编剧或助理导演当导演。TVDB 使用完整 extended 的 `characters.personName / peopleId / peopleType`；角色名 `name` 不作为演员姓名，不猜测未明确的职业。
- 同一来源的人物按 ID 去重，多角色合并；无 ID 时按姓名去重。有 ID 的同名人物仍独立。按来源的演员顺序展示，最多缓存 100 位演员及 50 位导演，截断时提示查看来源。人物照片与关联作品入口见下节；姓名和角色使用源返回值，不保证中文译名覆盖。
- **旧缓存无需清库**：重建并重启应用后，后台为已启用且有凭据的当前来源补齐演职员；也可点击“匹配 / 刷新到期资料”。只更新演职员字段，不重新下载有效标题/海报、不延长原 30 天期限、不改变手动选择和观看进度。
- 演职员请求失败不撤销已有影片资料、不触发另一源替换；失败状态及 **24 小时**重试时间写入缓存。到时后的扫描、重启或“匹配 / 刷新到期资料”批次再尝试，没有循环重试或定时媒体扫描。禁用来源不请求；成功返回空名单按正常缓存处理。手动重新确认作品会重新请求详情和演职员，仍受资料源冷却约束。
- 请求沿用 JSON 1 MiB、超时/限流和同源鉴权边界。TVDB 先获取短详情和海报，再独立请求完整 extended（不重复获取翻译），超大记录仅导致演职员不可用，不丢基本影片资料。

### 人物照片与关联作品

- 演员、导演均显示照片卡片，可点击照片或姓名进入人物页，再进入其关联作品详情。人物页支持按电影/电视剧筛选；未提供照片或加载失败时显示“暂无照片”，不生成或猜测人物肖像。
- 照片使用 TMDB `profile_path` / TVDB `personImgURL`。TVDB 的角色图片不冒充真实人物照片。仅从配置的图片来源读取，不接受客户端 URL、不跟随重定向，不向图片服务发送账号或资料源凭据；图片经服务器同源提供，原 CSP 不放宽。
- 照片按需获取，不阻塞扫描/标题匹配；独立图片缓存最长 **30 天**，失败 **24 小时**后再次访问才重试。缓存与失败间隔跨重启保留；凭据撤下后仍可读取有效缓存。已保存的公开图片引用可按需访问，不依赖重新登录资料 API。每张至多 5 MiB，只接收内容类型和签名一致的 JPEG/PNG/WebP；图片服务冷却独立于影片资料请求。
- 关联作品**仅来自当前媒体库的有效影片资料**，不查询外部完整作品年表。按来源 + 人物 ID 关联，同名但不同 ID、不同来源保持独立；来源未提供 ID 时仅关联当前作品，不根据姓名合并其他作品。
- 同一人物兼任演员/导演时合并到一部作品并显示两种身份；电视剧按整部作品计数，不重复列出单集。同来源、同类型、同作品 ID 的多个文件/目录合并为一个入口，优先进入可用的本地版本。已移除、已换绑、已到期的资料不会作为关联作品返回；没有有效关联时显示清晰提示。
- 人物与本地作品关系使用 SQLite 派生索引；升级后的首次启动会从已有影片资料补建，不访问外部服务或改动媒体文件。后续资料更新与索引更新处于同一事务，人物页只读取命中作品，不再逐份解析整个媒体库的演职员资料。
- **已有演职员也无需清库**：重新构建并重启后，启用且已配置的来源会补齐照片引用；也可使用“匹配 / 刷新到期资料”。补齐失败保留原姓名、角色和导演，并记录重试间隔，不改变标题、海报、手动选择、原资料期限或观看进度。真实照片覆盖由资料源决定；本功能的真实两源照片联通尚未实测。

## 手动修正影片资料（08）

在电影文件详情、电视剧详情或具体单集详情选择「手动匹配影片资料」，输入作品标题搜索目录已启用且有凭据的资料源。候选按目录优先级排列，展示类型、中文/原始标题、年份及来源和 ID；先选择正确作品，再点击「确认匹配」才保存。每个来源最多展示 20 个候选，更多结果时请细化标题。不同类型不会混用；取消、Esc 关闭、无结果或请求失败不会覆盖原有有效资料。

- 电影按**媒体文件标识**修改，同一电影不同实际版本互不合并；已组织的电视剧按**本地电视剧标识**修改，现有季集和文件关系不变。
- 未能识别季集的电视剧文件也可单独选择整部作品资料，但不因此推测季号/集号、不自动合并其他文件或生成季集层级。
- 所有搜索及确认均要求家庭共享账号，串流链接不能授权。确认时从对应来源的类型详情重新获取资料，成功后事务性保存；无凭据、超时、限流、外部失败或并发确认会反馈，不谎称成功。
- 手动选择在重扫/重启后保留；到期只刷新**已选来源和 ID**，不重新按文件名覆盖回自动结果。刷新失败后仍保留选择，资料暂时回退到本地信息，播放与进度不受影响。
- 操作不改名、移动、改写视频或字幕，不更换实际媒体文件身份。不提供 NFO 写回、批量手动匹配或永久离线资料保证。


### 从 04–06 播放版本升级

保留旧版可执行文件，构建新版后可在隔离数据上运行：

```bash
node scripts/verify-organization-upgrade.mjs /absolute/path/to/pre-tmdb-reelnest /absolute/path/to/current-reelnest --metadata
```

该模式先在真实旧版通过 HTTP 创建媒体、观看进度和串流地址，再模拟媒体离线升级，恢复原媒体后确认账号、文件/季集标识、旧观看进度和原串流凭证均保留；再次重启复核。测试清空 TMDB 凭据，既不请求真实资料服务，也不使用用户应用数据。
